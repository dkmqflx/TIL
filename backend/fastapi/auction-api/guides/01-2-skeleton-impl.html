구현 — 파일을 하나씩 만든다

아래 순서 그대로 따라 하세요. 각 코드 블록은 잘라낸 조각이 아니라 붙여넣으면 그대로 도는 전체 파일입니다. 오른쪽 위 "복사" 버튼을 쓰면 편합니다.

① uv 프로젝트 만들기

먼저 Python 버전을 고정하고, 그다음 프로젝트를 만듭니다. 순서가 중요합니다. uv init --bare는 pyproject.toml만 만들고 .python-version 파일은 만들지 않기 때문에, 먼저 pin을 하지 않으면 컴퓨터에 있는 가장 최신 Python(이 머신은 3.14)으로 가상환경이 잡힙니다. --bare는 "샘플 main.py나 README 같은 걸 만들지 말고 최소한만"이라는 뜻입니다.

bashtil/backend/fastapi/auction-api/
uv python pin 3.13
uv init --bare
uv add fastapi "uvicorn[standard]" "sqlalchemy[asyncio]" asyncpg redis pydantic-settings
uv add --dev ruff pytest httpx2

두 번째 uv add의 --dev는 "개발할 때만 필요한 도구"라는 뜻입니다. 운영 서버에 ruff나 pytest가 깔릴 필요는 없으니까요. httpx2는 테스트에서 쓸 TestClient가 요구하는 HTTP 라이브러리입니다. 예전 자료에는 httpx라고 돼 있는데, 이 프로젝트가 쓰는 Starlette 1.6부터는 httpx2를 요구합니다(아래 함정 참고).

설치가 끝나면 pyproject.toml이 생겨 있을 겁니다. 그 파일 맨 아래에 ruff와 pytest 설정을 붙여 넣습니다. ruff는 "코드 스타일 검사기 + 정리기"이고, select는 어떤 규칙을 켤지입니다(E/F는 기본 문법·오류, I는 import 정렬, UP은 최신 문법 권장, B는 흔한 버그 패턴).

tomlpyproject.toml — 맨 아래에 추가
[tool.ruff]
target-version = "py313"
line-length = 100

[tool.ruff.lint]
select = ["E", "F", "I", "UP", "B"]

[tool.pytest.ini_options]
testpaths = ["tests"]
검증 당시 버전. fastapi 0.141.1 · starlette 1.6.0 · sqlalchemy 2.0.52 · asyncpg 0.31.0 · redis 8.1.0 · pydantic-settings 2.15.0 · uvicorn 0.52.4 · httpx2 2.12.0 · pytest 9.1.1 · ruff 0.16.4. 이보다 새 버전이 깔려도 대부분 그대로 동작하지만, 뭔가 다르게 나오면 이 버전을 기준으로 비교하세요.

③ 폴더 구조 잡기

Week 6·02에서 배운 라우터·서비스·리포지토리 계층을 폴더로 미리 만들어 둡니다. 지금은 core와 routers만 채우고 나머지는 빈 패키지지만, "여기에 이런 게 들어간다"는 자리를 잡아 두는 겁니다. 파이썬에서 폴더를 패키지로 인식시키려면 __init__.py라는 빈 파일이 필요해서 touch로 만들어 줍니다.

④ Docker compose — Postgres와 Redis

Week 5·01에서 한 것과 같은 방식이지만 두 가지가 다릅니다. 첫째, Redis가 추가됐습니다. 둘째, 호스트 포트가 5435와 6380입니다. 이 머신에서 5432(Postgres 기본)와 5434는 이미 다른 프로젝트의 컨테이너가 쓰고 있어서, 겹치지 않는 번호를 골랐습니다. 콜론 왼쪽이 내 컴퓨터 쪽 포트, 오른쪽이 컨테이너 안쪽 포트입니다. 컨테이너 안에서는 여전히 기본 포트를 쓰고, 바깥에서 접속할 때만 5435로 들어갑니다.

yamldocker-compose.yml
services:
  db:
    image: postgres:16-alpine
    container_name: auction-db
    environment:
      POSTGRES_USER: auction
      POSTGRES_PASSWORD: auction_pw
      POSTGRES_DB: auction
    ports:
      - "5435:5432"
    volumes:
      - auction-pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U auction -d auction"]
      interval: 5s
      timeout: 3s
      retries: 5

  redis:
    image: redis:7-alpine
    container_name: auction-redis
    ports:
      - "6380:6379"
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 5s
      timeout: 3s
      retries: 5

volumes:
  auction-pgdata:

healthcheck는 Docker가 몇 초마다 "이 컨테이너 제대로 살아 있니?"를 확인하는 명령입니다. docker compose ps에서 (healthy)라고 뜨면 접속해도 된다는 뜻입니다. volumes는 컨테이너를 지워도 DB 데이터가 남도록 별도 저장소를 붙이는 설정입니다.

⑤ 환경 파일 — .env.example과 .env

설정값은 코드에 박지 않고 .env 파일에서 읽습니다. 그런데 .env는 git에 안 올리기로 했으니, 새로 합류한 사람은 "어떤 키가 필요한지" 알 수가 없습니다. 그래서 비밀이 아닌 예시값을 담은 .env.example을 함께 두고 커밋합니다. 지금은 개발용이라 둘의 내용이 같지만, 습관을 들이는 게 목적입니다.

env.env.example
APP_ENV=dev
DATABASE_URL=postgresql+asyncpg://auction:auction_pw@localhost:5435/auction
REDIS_URL=redis://localhost:6380/0
DEBUG=true
bash
cp .env.example .env

DATABASE_URL을 뜯어보면 postgresql+asyncpg://는 "Postgres를 asyncpg 드라이버로", auction:auction_pw는 사용자와 비밀번호, localhost:5435는 compose에서 열어 둔 포트, 마지막 /auction은 DB 이름입니다. compose 파일의 값과 하나라도 다르면 접속이 안 되니 대조해 보세요.

⑥ 테스트부터 — tests/test_health.py

이제 코드를 쓸 차례인데, 구현보다 테스트를 먼저 씁니다. "이런 결과가 나와야 한다"를 먼저 적어 두고, 그걸 통과시키는 방식으로 구현하면 뭘 만들어야 하는지가 명확해집니다(4단계부터는 이 방식을 본격적으로 씁니다). with TestClient(app) as client:처럼 with 블록 안에서 쓰면 lifespan의 시작·종료가 실제로 실행됩니다.

pythontests/test_health.py
from fastapi.testclient import TestClient

from app.main import app


def test_health_reports_db_and_redis():
    with TestClient(app) as client:
        res = client.get("/health")
    assert res.status_code == 200
    assert res.json() == {"status": "ok", "db": True, "redis": True}

지금 실행하면 당연히 실패합니다. app.main이 아직 없으니까요. 그래도 한 번 돌려 보세요. "실패하는 걸 눈으로 확인하고 → 통과시킨다"가 TDD의 리듬입니다.

⑦ app/core/config.py — 설정 열쇠고리

BaseSettings를 상속한 클래스는 필드 이름과 같은 환경변수(대소문자 무시)를 자동으로 읽습니다. env_file=".env"를 주면 .env 파일도 읽는데, 우선순위는 진짜 환경변수 > .env 파일 > 코드의 기본값입니다. 그래서 CI나 운영 서버에서는 .env 없이 환경변수만 넣어도 되고, 로컬에서는 .env만 있으면 됩니다.

pythonapp/core/config.py
from functools import lru_cache
from typing import Literal

from pydantic_settings import BaseSettings, SettingsConfigDict


class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_file=".env", env_file_encoding="utf-8", extra="ignore")

    app_env: Literal["dev", "test", "prod"] = "dev"
    database_url: str = "postgresql+asyncpg://auction:auction_pw@localhost:5435/auction"
    redis_url: str = "redis://localhost:6380/0"
    debug: bool = False


@lru_cache
def get_settings() -> Settings:
    return Settings()

Literal["dev", "test", "prod"]는 "이 셋 중 하나만 허용"이라는 타입입니다. 오타로 APP_ENV=prd라고 적으면 앱이 뜨는 순간 에러가 나서 바로 알 수 있습니다. @lru_cache는 get_settings()를 아무리 많이 불러도 .env 파일은 딱 한 번만 읽게 해 주는 장식자입니다. 요청마다 파일을 다시 읽을 이유가 없으니까요.

⑧ app/core/db.py — 비동기 엔진과 세션

Week 7·01에서 배운 async SQLAlchemy 구성입니다. engine은 "DB에 어떻게 접속하는지 아는 객체 + 커넥션 풀"이고, SessionLocal은 "세션을 찍어내는 공장", get_db는 요청마다 세션 하나를 열어서 건네주고 요청이 끝나면 닫아 주는 의존성입니다. Week 6·02의 yield 의존성과 모양이 같은데 async가 붙었을 뿐입니다.

pythonapp/core/db.py
from collections.abc import AsyncIterator

from sqlalchemy.ext.asyncio import AsyncSession, async_sessionmaker, create_async_engine

from app.core.config import get_settings

engine = create_async_engine(get_settings().database_url, pool_pre_ping=True)
SessionLocal = async_sessionmaker(engine, expire_on_commit=False)


async def get_db() -> AsyncIterator[AsyncSession]:
    async with SessionLocal() as session:
        yield session

engine을 함수 안이 아니라 파일 맨 위(모듈 수준)에서 만드는 게 의아할 수 있는데, create_async_engine은 이 줄이 실행되는 순간 DB에 접속하지 않습니다. 접속 정보만 기억해 뒀다가 첫 쿼리가 나갈 때 연결합니다. 그래서 import만 해도 안전하고, 정리(dispose)만 lifespan에서 해 주면 됩니다.

⑨ app/core/redis.py — Redis 클라이언트

같은 패턴입니다. Redis.from_url도 실제 연결은 첫 명령 때 맺습니다. decode_responses=True는 Redis가 돌려주는 값을 바이트가 아니라 문자열로 받겠다는 뜻으로, 매번 .decode()를 안 해도 돼서 편합니다.

pythonapp/core/redis.py
from redis.asyncio import Redis

from app.core.config import get_settings

redis_client: Redis = Redis.from_url(get_settings().redis_url, decode_responses=True)


def get_redis() -> Redis:
    return redis_client

⑩ app/routers/health.py — 진짜로 확인하는 헬스체크

"살아 있어요"만 돌려주는 헬스체크는 앱 프로세스가 떠 있다는 것밖에 증명하지 못합니다. 이 엔드포인트는 DB에 SELECT 1, Redis에 PING을 실제로 보내서 각각 성공했는지를 따로 보고합니다. 하나라도 실패하면 503으로 응답하는데, 이유는 아래 함정 절에서 설명합니다.

pythonapp/routers/health.py
from typing import Annotated

from fastapi import APIRouter, Depends, Response, status
from redis.asyncio import Redis
from sqlalchemy import text
from sqlalchemy.ext.asyncio import AsyncSession

from app.core.db import get_db
from app.core.redis import get_redis

router = APIRouter(tags=["health"])


@router.get("/health")
async def health(
    response: Response,
    db: Annotated[AsyncSession, Depends(get_db)],
    redis: Annotated[Redis, Depends(get_redis)],
) -> dict[str, str | bool]:
    db_ok = False
    redis_ok = False
    try:
        await db.execute(text("SELECT 1"))
        db_ok = True
    except Exception:
        pass
    try:
        redis_ok = bool(await redis.ping())
    except Exception:
        pass

    ok = db_ok and redis_ok
    if not ok:
        response.status_code = status.HTTP_503_SERVICE_UNAVAILABLE
    return {"status": "ok" if ok else "degraded", "db": db_ok, "redis": redis_ok}

db: Annotated[AsyncSession, Depends(get_db)]는 Week 6·02의 Annotated 스타일 그대로입니다. 인자에 response: Response를 받으면 응답 본문은 그대로 return하면서 상태 코드만 바꿀 수 있습니다. except Exception: pass는 평소엔 나쁜 습관이지만 헬스체크만큼은 예외입니다 — "연결이 됐나 안 됐나"만 알면 되고, 어떤 이유로 실패했든 결과는 False이기 때문입니다.

⑪ app/main.py — 앱 조립과 lifespan

create_app()이라는 함수로 앱을 만드는 이유는 나중에 테스트에서 "설정만 다른 앱"을 하나 더 만들기 쉽게 하려는 겁니다. lifespan은 yield를 기준으로 위가 시작, 아래가 종료인데, 이번 단계에서는 시작 때 할 일이 없어서(엔진·클라이언트는 이미 import 때 만들어졌으니) 종료 정리만 넣었습니다.

pythonapp/main.py
from collections.abc import AsyncIterator
from contextlib import asynccontextmanager

from fastapi import FastAPI

from app.core.config import get_settings
from app.core.db import engine
from app.core.redis import redis_client
from app.routers import health


@asynccontextmanager
async def lifespan(app: FastAPI) -> AsyncIterator[None]:
    yield
    await redis_client.aclose()
    await engine.dispose()


def create_app() -> FastAPI:
    settings = get_settings()
    app = FastAPI(title="Auction API", debug=settings.debug, lifespan=lifespan)
    app.include_router(health.router)
    return app


app = create_app()
