2. tests/test_ws.py — 진짜 서버에 붙는다

3단계에서 우리는 pytest 전체가 세션 루프 하나에서 돌게 정했고, 앱의 DB 풀·Redis 클라이언트도 그 루프에 묶여 있습니다. Starlette 의 TestClient(websocket_connect 가 있는 그것)는 별도 스레드에 자기 루프를 만들어 앱을 돌립니다. 그 루프에서 우리 풀의 커넥션을 쓰면 attached to a different loop 로 깨집니다. 우회하느니 정공법으로 갑니다 — live_server fixture 가 python -m uvicorn app.main:app --port 8765 를 자식 프로세스로 띄우고 /health 가 200 을 줄 때까지 기다립니다. 환경변수(DATABASE_URL=auction_test, REDIS_URL=15번 DB)는 conftest 가 이미 바꿔 둔 것을 자식이 그대로 물려받으니, 자식 서버도 테스트 DB 를 봅니다.

덤으로 얻는 게 큽니다. "다른 프로세스(자식 서버)가 커밋하고 발행한 이벤트가 Redis 를 거쳐 내 소켓에 온다"는 이 단계의 주장이 테스트 자체로 증명됩니다. 데이터는 자식이 봐야 하니 @pytest.mark.commits — 6단계처럼 진짜 커밋하고 끝에 TRUNCATE 합니다. 테스트 다섯 개: 토큰 없음 → 4401, 없는 경매 → 4404, snapshot 뒤 입찰 → bid_placed, 구독자 둘이 같은 이벤트, 끊긴 소켓이 있어도 남은 소켓은 정상.

pythontests/test_ws.py
"""WebSocket 실시간 테스트 — 앱을 **진짜 서버(uvicorn 자식 프로세스)** 로 띄우고 붙는다.

왜 TestClient 가 아닌가: Starlette TestClient 는 별도 스레드·별도 이벤트 루프에서 앱을 돌린다.
우리 앱의 DB 풀·Redis 클라이언트는 pytest 의 세션 루프에 묶여 있어서(3단계 결정) 다른 루프에서

    return json.loads(await asyncio.wait_for(ws.recv(), timeout))

4. app/core/events.py — 이벤트 한 장과 publish()

이벤트는 type·auction_id·payload·at 네 칸짜리 Pydantic 모델입니다. model_dump_json() 이 UUID 와 datetime 을 알아서 문자열로 바꿔 주니 json.dumps 로 씨름할 일이 없습니다. publish() 는 PUBLISH auction:{id} … 한 줄이고 받은 구독자 수를 돌려줍니다 — 0 이어도 정상입니다(아무도 안 보고 있을 뿐). 채널 이름을 만드는 함수와 되돌리는 함수를 여기 같이 둬서, 채널 규칙이 바뀌면 이 파일만 고칩니다.

pythonapp/core/events.py
"""도메인 이벤트 — "경매 X 에 이런 일이 있었다" 를 한 줄(JSON)로 만들어 Redis 채널에 방송한다.

서비스는 이 모듈의 publish() 만 알면 된다. 누가 듣고 있는지(웹소켓? 알림 워커? 아무도?) 는
서비스가 신경 쓰지 않는다 — 그게 Pub/Sub 의 요점이다. 채널 이름은 auction:{id} 하나로 통일한다.
"""

import uuid
from datetime import UTC, datetime
from typing import Any

from pydantic import BaseModel, Field
from redis.asyncio import Redis

CHANNEL_PREFIX = "auction:"


class AuctionEvent(BaseModel):
    type: str  # "snapshot" | "bid_placed" | (8단계) "auction_closed" …
    auction_id: uuid.UUID
    payload: dict[str, Any] = Field(default_factory=dict)
    at: datetime = Field(default_factory=lambda: datetime.now(UTC))


def channel(auction_id: uuid.UUID | str) -> str:
    return f"{CHANNEL_PREFIX}{auction_id}"


def auction_id_from_channel(name: str) -> str:
    return name.removeprefix(CHANNEL_PREFIX)


async def publish(redis: Redis, event: AuctionEvent) -> int:
    """구독자 수를 돌려준다(듣는 사람이 없으면 0 — 그래도 에러는 아니다).
    model_dump_json() 이 UUID·datetime 을 문자열로 바꿔 준다."""
    return await redis.publish(channel(event.auction_id), event.model_dump_json())

5. app/ws/manager.py — 이 프로세스의 장부

9주차·01 의 ConnectionManager 와 같은 물건인데 두 가지가 다릅니다. (1) accept() 를 여기서 하지 않습니다 — 라우터가 인증을 끝낸 뒤 등록만 부탁합니다. (2) broadcast 가 asyncio.gather(…, return_exceptions=True) 로 동시에 보내고, 실패한 소켓(이미 끊긴 것)은 조용히 장부에서 지웁니다. 하나가 죽었다고 나머지가 못 받으면 안 되니까요. 그리고 이 장부는 프로세스 안에만 있습니다 — 그 한계를 다음 파일이 메웁니다.

pythonapp/ws/manager.py
"""ConnectionManager — **이 프로세스에** 붙어 있는 소켓들을 경매별로 묶어 두는 장부.

프로세스(워커)마다 하나씩 있고, 다른 워커의 소켓은 모른다. 워커 사이를 잇는 건 bridge.py 다.
"""

import asyncio
import logging
import uuid

from fastapi import WebSocket

logger = logging.getLogger(__name__)


class ConnectionManager:
    def __init__(self) -> None:
        self._rooms: dict[str, set[WebSocket]] = {}

    def connect(self, auction_id: uuid.UUID | str, ws: WebSocket) -> None:
        """accept() 는 라우터가 이미 했다 — 여기선 장부에 적기만."""
        self._rooms.setdefault(str(auction_id), set()).add(ws)

    def disconnect(self, auction_id: uuid.UUID | str, ws: WebSocket) -> None:
        room = self._rooms.get(str(auction_id))
        if room is None:
            return
        room.discard(ws)
        if not room:
            del self._rooms[str(auction_id)]

    def count(self, auction_id: uuid.UUID | str) -> int:
        return len(self._rooms.get(str(auction_id), ()))

    async def broadcast(self, auction_id: uuid.UUID | str, text: str) -> None:
        """방 안의 모두에게 동시에 보낸다. 끊긴 소켓은 조용히 장부에서 지운다."""
        room = list(self._rooms.get(str(auction_id), ()))
        if not room:
            return
        results = await asyncio.gather(*(ws.send_text(text) for ws in room), return_exceptions=True)
        for ws, result in zip(room, results, strict=True):
            if isinstance(result, Exception):
                logger.info("dead socket removed (auction=%s): %s", auction_id, result)
                self.disconnect(auction_id, ws)


manager = ConnectionManager()

6. app/ws/bridge.py — 워커마다 수신기 하나

redis.pubsub() 으로 전용 연결을 만들고 psubscribe("auction:*") — 경매가 몇 개든 패턴 하나로 다 듣습니다. 루프는 get_message(timeout=1.0) 을 씁니다. listen() 처럼 영원히 막히는 호출 대신 1초마다 깨어나야 서버가 내려갈 때 cancel() 을 제때 받아 구독을 정리할 수 있습니다. 메시지가 오면 채널 이름에서 경매 id 를 꺼내 manager.broadcast — 내용은 열어 보지도 않고 그대로 넘깁니다. bridge 는 중계기일 뿐 서비스가 뭘 보냈는지 모릅니다(그래서 redis-cli 로 쏜 아무 문자열도 소켓에 그대로 나옵니다).

pythonapp/ws/bridge.py
"""Redis 구독 → 이 프로세스의 소켓들로 중계.

워커가 2개면 이 루프도 2개(프로세스마다 하나) 돈다. 어느 워커가 입찰을 처리해 PUBLISH 하든
모든 워커의 루프가 같은 메시지를 받아 *자기* 소켓들에게 뿌린다. 그래서 클라이언트가 어느 워커에
붙었는지는 상관없어진다.
"""

import asyncio
import logging

from redis.asyncio import Redis

from app.core.events import CHANNEL_PREFIX, auction_id_from_channel
from app.ws.manager import ConnectionManager

logger = logging.getLogger(__name__)


async def run_bridge(redis: Redis, manager: ConnectionManager) -> None:
    """lifespan 이 create_task() 로 띄우고, 종료 때 cancel() 한다."""
    pubsub = redis.pubsub()
    await pubsub.psubscribe(f"{CHANNEL_PREFIX}*")  # auction:* 전부
    logger.info("pubsub bridge started")
    try:
        while True:
            # timeout 을 주는 이유: 메시지가 없어도 1초마다 깨어나 cancel 을 받아 줄 수 있게.
            msg = await pubsub.get_message(ignore_subscribe_messages=True, timeout=1.0)
            if msg is None:
                continue
            auction_id = auction_id_from_channel(msg["channel"])
            await manager.broadcast(auction_id, msg["data"])
    except asyncio.CancelledError:
        logger.info("pubsub bridge stopping")
        raise
    finally:
        await pubsub.punsubscribe()
        await pubsub.aclose()

7. app/ws/router.py — 소켓의 일생

위 둘째 그림 그대로입니다. 세 가지만 짚습니다. accept 먼저 — 그래야 close(code=4401) 가 클라이언트에 코드로 전달됩니다. DB 세션은 SessionLocal() 로 직접, 짧게 — Depends(get_db) 로 받으면 소켓이 살아 있는 내내(몇 분, 몇 시간) 커넥션 하나를 붙들고 있게 됩니다. receive_text() 루프 — 서버는 클라이언트 메시지를 쓰지 않지만, 이 대기가 없으면 함수가 끝나며 소켓이 닫힙니다. 클라이언트가 끊으면 WebSocketDisconnect 로 빠져나와 finally 에서 장부를 정리합니다. served_by_pid 는 순전히 데모용입니다(어느 워커에 붙었는지 눈으로 보려고). 운영에선 빼세요.

pythonapp/ws/router.py
"""WS /ws/auctions/{auction_id}?token=… — 경매 하나를 구독한다.

순서: accept → 토큰 확인(실패면 4401 로 close) → 경매 확인(없으면 4404) → snapshot 한 장 보내기
→ 장부에 등록 → 클라이언트가 끊을 때까지 대기.

왜 accept 부터 하나: accept 전에 close 하면 서버는 HTTP 403 으로 핸드셰이크 자체를 거절한다.
그러면 클라이언트는 "왜" 를 알 수 없다. accept 뒤에 close(code=4401) 를 보내면 클라이언트가
close 코드를 읽어 "토큰 문제구나" 하고 처리할 수 있다. 4000~4999 는 앱이 마음대로 쓰는 구간.

DB 세션은 Depends(get_db) 로 받지 않는다 — 그러면 소켓이 살아 있는 내내 커넥션을 쥐고 있게 된다.
필요한 순간(인증·snapshot)에만 세션을 열고 바로 닫는다.
"""

import os
import uuid

from fastapi import APIRouter, WebSocket, WebSocketDisconnect

from app.core.db import SessionLocal
from app.core.events import AuctionEvent
from app.core.security import TokenError, decode_token
from app.repositories import auction as auction_repo
from app.repositories import user as user_repo
from app.ws.manager import manager

router = APIRouter(tags=["realtime"])

WS_UNAUTHORIZED = 4401
WS_NOT_FOUND = 4404


async def _user_id_from_token(token: str | None) -> uuid.UUID | None:
    if not token:
        return None
    try:
        payload = decode_token(token, expected_type="access")
    except TokenError:
        return None
    user_id = uuid.UUID(payload["sub"])
    async with SessionLocal() as db:
        if await user_repo.get_by_id(db, user_id) is None:
            return None
    return user_id


@router.websocket("/ws/auctions/{auction_id}")
async def auction_stream(ws: WebSocket, auction_id: uuid.UUID, token: str | None = None) -> None:
    await ws.accept()

    if await _user_id_from_token(token) is None:
        await ws.close(code=WS_UNAUTHORIZED, reason="invalid or missing token")
        return

    async with SessionLocal() as db:
        auction = await auction_repo.get(db, auction_id)
        if auction is None:
            await ws.close(code=WS_NOT_FOUND, reason="auction not found")
            return
        snapshot = AuctionEvent(
            type="snapshot",
            auction_id=auction.id,
            payload={
                "status": auction.status,
                "current_price": auction.current_price,
                "bid_count": auction.bid_count,
                "ends_at": auction.ends_at,
                "version": auction.version,
                "served_by_pid": os.getpid(),  # 데모용 — 어느 워커에 붙었는지 눈으로 확인
            },
        )
    await ws.send_text(snapshot.model_dump_json())

    manager.connect(auction_id, ws)
    try:
        while True:
            await ws.receive_text()  # 클라이언트 ping 등. 끊기면 WebSocketDisconnect
    except WebSocketDisconnect:
        pass
    finally:
        manager.disconnect(auction_id, ws)

8. app/services/bid.py — 커밋 뒤에 한 줄

바뀐 건 두 군데뿐입니다. 스나이핑 연장이 일어났는지 extended 로 기억해 두고, db.commit()·refresh 가 끝난 다음에 events.publish(). 순서가 전부입니다 — 커밋 전에 방송하면 구독자가 아직 DB 에 없는 입찰을 보고, 커밋이 실패하면 "없던 일"이 방송된 채 남습니다. payload 에는 증분이 아니라 현재 값(current_price·bid_count·ends_at·version)을 통째로 싣습니다. 한 건 놓쳐도 다음 건이 화면을 바로잡게.

이벤트를 하나로 합친 이유. 연장이 일어났을 때 bid_placed 와 auction_extended 를 따로 두 번 쏠 수도 있습니다. 하지만 클라이언트가 두 이벤트 사이에서 잠깐 불일치한 화면을 그리게 되고, 순서 보장도 신경 써야 합니다. "입찰 한 건 = 이벤트 한 건"에 extended: true 플래그를 얹는 쪽이 단순합니다. 8단계의 auction_closed 처럼 다른 사건일 때만 type 을 나눕니다.
python(수정) app/services/bid.py
"""입찰 규칙. HTTP 를 모른다 — 도메인 예외만 던진다.

핵심은 순서다: (rate limit) → **경매 행 잠금** → 규칙 검사 → 갱신 → 커밋.
잠금부터 커밋까지가 한 트랜잭션이라, 그 사이에 다른 입찰은 줄을 서서 기다린다.
그래서 '현재가 + 최소 단위' 를 계산할 때 본 값이 커밋하는 순간까지 그대로다.
"""

import uuid
from datetime import UTC, datetime, timedelta

from redis.asyncio import Redis
from sqlalchemy.ext.asyncio import AsyncSession

from app.core import events
from app.core.config import get_settings
from app.core.exceptions import (
    AuctionNotActiveError,
    AuctionNotFoundError,
    BidRateLimitedError,
    BidTooLowError,
    OwnAuctionBidError,
)
from app.models import Auction, AuctionStatus, Bid, User
from app.repositories import auction as auction_repo
from app.repositories import bid as bid_repo


def _now() -> datetime:
    """시계를 함수로 빼 두면 테스트에서 멈추거나 돌릴 수 있다."""
    return datetime.now(UTC)


async def _check_rate_limit(redis: Redis, user_id: uuid.UUID, now: datetime) -> None:
    """사용자별 '이번 1초' 카운터. INCR 는 원자적이라 동시에 들어와도 정확히 센다."""
    key = f"bid:rl:{user_id}:{int(now.timestamp())}"
    count = await redis.incr(key)
    if count == 1:
        await redis.expire(key, 2)  # 1초짜리 키가 영원히 남지 않도록
    if count > get_settings().bid_rate_limit_per_second:
        raise BidRateLimitedError()


def minimum_bid(auction: Auction) -> int:
    """첫 입찰은 시작가 이상, 그 다음부터는 현재가 + 최소 단위 이상."""
    if auction.bid_count == 0:
        return auction.starting_price
    return auction.current_price + auction.min_increment


async def place_bid(
    db: AsyncSession, redis: Redis, bidder: User, auction_id: uuid.UUID, amount: int
) -> tuple[Bid, Auction]:
    settings = get_settings()
    now = _now()

    await _check_rate_limit(redis, bidder.id, now)  # 락을 잡기 *전에* — 스팸이 락을 쥐고 있지 않게

    auction = await auction_repo.get_for_update(db, auction_id)  # ← 여기서부터 줄을 선다
    if auction is None:
        raise AuctionNotFoundError()
    if auction.status != AuctionStatus.ACTIVE or now >= auction.ends_at:
        raise AuctionNotActiveError()
    if auction.seller_id == bidder.id:
        raise OwnAuctionBidError()
    minimum = minimum_bid(auction)
    if amount < minimum:
        raise BidTooLowError(
            f"최소 입찰액은 {minimum:,}원입니다 (현재가 {auction.current_price:,}원)"
        )

    # 규칙 4 — 마감 직전 입찰이면 마감을 늦춘다 (스나이핑 방지)
    extended = False
    if auction.ends_at - now < timedelta(seconds=settings.snipe_window_seconds):
        auction.ends_at = auction.ends_at + timedelta(seconds=settings.snipe_extend_seconds)
        extended = True

    auction.current_price = amount
    auction.bid_count += 1
    auction.version += 1
    bid = Bid(auction_id=auction.id, bidder_id=bidder.id, amount=amount)
    await bid_repo.add(db, bid)

    await db.commit()  # ← 여기서 락이 풀리고, 줄 서 있던 다음 입찰이 '바뀐 현재가' 를 본다
    await db.refresh(bid)
    await db.refresh(auction)

    # 커밋 *뒤에* 방송한다. 커밋 전에 방송하면 구독자가 "아직 DB 에 없는 입찰" 을 보게 되고,
    # 커밋이 실패하면 없던 일이 방송된 채로 남는다.
    await events.publish(
        redis,
        events.AuctionEvent(
            type="bid_placed",
            auction_id=auction.id,
            payload={
                "amount": bid.amount,
                "bidder_id": bid.bidder_id,
                "current_price": auction.current_price,
                "bid_count": auction.bid_count,
                "ends_at": auction.ends_at,
                "version": auction.version,
                "extended": extended,
            },
        ),
    )
    return bid, auction


async def list_bids(db: AsyncSession, auction_id: uuid.UUID) -> list[Bid]:
    if await auction_repo.get(db, auction_id) is None:
        raise AuctionNotFoundError()
    return await bid_repo.list_by_auction(db, auction_id)

9. app/main.py — 수신기 켜기, 라우터, 정적 파일

lifespan 이 드디어 시작 쪽 일을 합니다: asyncio.create_task(run_bridge(...)). --workers 2 면 프로세스마다 lifespan 이 돌아 bridge 도 2개가 됩니다(그림 1). 종료 때는 cancel() 하고 기다린 뒤 Redis·엔진을 닫습니다 — 순서를 바꾸면 bridge 가 닫힌 Redis 에 punsubscribe 를 보내다 에러가 납니다. /static 마운트는 데모 페이지용이며 경로를 __file__ 기준으로 잡아 어디서 실행해도 같은 폴더를 봅니다.

python(수정) app/main.py
import asyncio
import pathlib
from collections.abc import AsyncIterator
from contextlib import asynccontextmanager

from fastapi import FastAPI
from fastapi.staticfiles import StaticFiles

from app.core.config import get_settings
from app.core.db import engine
from app.core.exceptions import register_exception_handlers
from app.core.redis import redis_client
from app.routers import auctions, auth, bids, health, users
from app.ws import router as ws_router
from app.ws.bridge import run_bridge
from app.ws.manager import manager

STATIC_DIR = pathlib.Path(__file__).resolve().parent.parent / "static"


@asynccontextmanager
async def lifespan(app: FastAPI) -> AsyncIterator[None]:
    # 프로세스(워커)마다 Redis 구독 루프 하나 — 이 워커에 붙은 소켓들에게 이벤트를 중계한다
    bridge = asyncio.create_task(run_bridge(redis_client, manager))
    yield
    bridge.cancel()
    try:
        await bridge
    except asyncio.CancelledError:
        pass
    await redis_client.aclose()
    await engine.dispose()


def create_app() -> FastAPI:
    settings = get_settings()
    app = FastAPI(title="Auction API", debug=settings.debug, lifespan=lifespan)
    register_exception_handlers(app)
    app.include_router(health.router)
    app.include_router(auth.router)
    app.include_router(users.router)
    app.include_router(auctions.router)
    app.include_router(bids.router)
    app.include_router(ws_router.router)
    app.mount("/static", StaticFiles(directory=STATIC_DIR), name="static")
    return app


app = create_app()

11. scripts/ws_listen.py — 터미널에서 듣기

실행·확인에서 워커 2개를 증명할 때 씁니다. 지정한 초 동안 받은 이벤트를 [type] payload 로 찍고 끝납니다.

pythonscripts/ws_listen.py
"""터미널용 구독 클라이언트: uv run python scripts/ws_listen.py <auction_id> <token> [초]

받은 이벤트를 한 줄씩 찍는다. 워커가 여럿일 때 snapshot 의 served_by_pid 로
"나는 어느 워커에 붙었나" 를 확인하는 용도.
"""

import asyncio
import json
import sys

from websockets.asyncio.client import connect


async def main(auction_id: str, token: str, seconds: float) -> None:
    url = f"ws://127.0.0.1:8000/ws/auctions/{auction_id}?token={token}"
    async with connect(url) as ws:
        loop = asyncio.get_running_loop()
        deadline = loop.time() + seconds
        while (remaining := deadline - loop.time()) > 0:
            try:
                raw = await asyncio.wait_for(ws.recv(), timeout=remaining)
            except TimeoutError:
                break
            ev = json.loads(raw)
            print(f"[{ev['type']}] {json.dumps(ev['payload'], ensure_ascii=False)}", flush=True)


if __name__ == "__main__":
    asyncio.run(main(sys.argv[1], sys.argv[2], float(sys.argv[3]) if len(sys.argv) > 3 else 15))
