실시간 경매 API — 10단계 캡스톤

self-study에서 배운 것을 실제 서비스 모양으로 옮기는 프로젝트입니다. 단계마다 가이드 한 편을 따라 하면 기능이 하나씩 동작하고, 10단계가 끝나면 회원가입 → 경매 등록 → 실시간 입찰 → 자동 마감 → 결제까지 흐르는 백엔드가 완성됩니다.

FastAPI SQLAlchemy 2.0 async PostgreSQL Redis JWT WebSocket pytest Docker / CI
📖

이 프로젝트는

왜 하필 경매냐면, 실무 백엔드에서 매일 마주치는 어려운 문제들이 억지로 끼워 넣은 게 아니라 도메인상 당연히 나오기 때문입니다. 두 명이 0.1초 차이로 입찰하면 누가 이기는지(동시성), 입찰 현황이 모든 접속자에게 바로 보여야 하고(실시간), 마감 시각이 되면 누가 낙찰자인지 자동으로 정해져야 하며(시간 기반 처리), 결제는 외부 PG가 웹훅으로 알려 줍니다(외부 연동). 이슈 트래커나 블로그로는 이런 문제를 진짜로 겪어 보기 어렵습니다.

각 단계는 두 가지를 합니다. 하나는 self-study의 특정 주차 내용을 실무 코드 모양으로 옮기는 것이고, 다른 하나는 커리큘럼에 없었지만 실무에선 필수인 요소를 하나씩 보태는 것입니다. 예를 들어 2단계는 Week 5·7의 SQLAlchemy를 옮기면서 "처음부터 마이그레이션"을 보태고, 6단계는 Week 4·5의 락 개념을 옮기면서 "동시 50건 테스트"를 보탭니다.

진행 방법. 한 단계는 세 개의 문서로 나뉩니다 — N-1 개요와 설계(왜 하는지·무엇을 만드는지), N-2 구현(파일을 하나씩 만드는 부분), N-3 실행·확인(진짜 도는지 확인하고 단계를 닫는 부분). 9·10단계는 구현이 커서 N-2 / N-3 둘로 갈라져 네 문서입니다. 왼쪽 사이드바와 문서 위쪽 탭으로 오갈 수 있고, 마지막의 "완료 기준 체크리스트"가 전부 체크되면 커밋하고 다음 단계로 넘어가세요. 설계 전체가 궁금하면 설계 문서를 보세요.
🧰

사전 준비

시작 전에 네 가지만 확인하면 됩니다. 아래 명령이 전부 에러 없이 돌아가야 합니다.

bash
uv --version                 # uv 패키지 관리자
docker ps                    # Docker Desktop 실행 중
uv python list | grep 3.13   # Python 3.13 설치됨 (없으면 uv python install 3.13)
lsof -i :5435 -i :6380       # 아무것도 안 나와야 함 (포트 비어 있음)
포트가 5432가 아닌 이유. 이 머신에서는 다른 프로젝트 컨테이너가 5432·5434를 쓰고 있어서, 이 프로젝트는 Postgres 5435, Redis 6380, 앱 8000, 모의 결제 서버 8001을 씁니다. 모든 가이드와 설정 파일이 이 번호를 기준으로 합니다.

도메인 요약

엔티티는 네 개뿐입니다. User는 판매자이면서 입찰자입니다. Auction은 물건 하나의 경매로 시작가·현재가·최소 입찰 단위·시작/마감 시각·상태(scheduled → active → ended | cancelled)·낙찰자를 가집니다. Bid는 "누가 어느 경매에 얼마를"이고, Payment는 낙찰 후 생기는 결제 건(pending → paid | expired)입니다.

규칙은 여섯 개이고, 이게 곧 6~9단계의 테스트 케이스가 됩니다.

  1. 본인이 올린 경매에는 입찰할 수 없다.
  2. active 상태에서만 입찰할 수 있다.
  3. 입찰액은 현재가 + 최소 입찰 단위 이상이어야 한다 (첫 입찰은 시작가 이상).
  4. 마감 30초 이내에 입찰이 들어오면 마감을 30초 연장한다 (스나이핑 방지).
  5. 마감 시 최고 입찰자가 낙찰자가 되고, 24시간짜리 결제 건이 생긴다. 입찰이 없으면 유찰.
  6. 결제 기한 안에 결제하지 않으면 결제 건은 만료된다 (차순위 승계는 하지 않는다).

완주 후 — 다음 갈 길

10단계까지 끝냈다면 "동작하는 백엔드를 운영 모양으로 만드는 한 바퀴" 를 돌아 본 것입니다. 다음은 같은 코드에 실무 부품을 하나씩 갈아 끼우는 연습입니다. 진짜 PG(토스·포트원) — pg_client 의 URL·본문·서명 규칙만 그 문서대로 바꾸고 Idempotency-Key 를 붙여 보세요. 작업 큐(arq·Celery) — 8단계 워커의 폴링 루프를 "마감 시각에 예약된 잡" 으로 바꿔 보세요. OpenTelemetry — 10단계의 request-id 를 trace-id 로 승격시켜 SQL·httpx 스팬까지 한 화면에서 보세요. Kubernetes — compose 의 다섯 서비스를 Deployment 로 옮기고 liveness/readiness 를 나눠 보세요. 그리고 README.md 의 회고 세 줄을 채우는 것이 진짜 마지막입니다.
