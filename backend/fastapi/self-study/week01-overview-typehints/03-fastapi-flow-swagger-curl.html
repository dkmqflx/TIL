첫 FastAPI 앱 — 동작 흐름 · Swagger · cURL

이론을 손으로 옮길 차례입니다. uv로 환경을 만들고, 첫 엔드포인트를 띄우고, 브라우저와 터미널에서 직접 두드려 봅니다.

한 줄 요약. 요청은 Uvicorn(서버) → FastAPI(앱) → 경로 함수 순서로 흐르고, 반환값은 자동으로 JSON이 되어 되돌아온다. /docs를 열면 문서가 이미 만들어져 있다.

학습 목표

  • uv로 FastAPI 프로젝트를 세팅하고 서버를 띄운다
  • 요청이 Uvicorn → FastAPI → 경로 함수로 흐르는 과정을 그린다
  • 자동 생성되는 Swagger UI / ReDoc를 활용한다
  • cURL로 터미널에서 API를 테스트한다
⚙️

uv로 30초 환경 세팅

uv는 Rust로 만든 초고속 Python 패키지 매니저입니다. 프로젝트 생성, 라이브러리 설치, 가상환경 관리를 명령 하나로 처리합니다. Node를 써봤다면 아래 표의 대응만 보면 됩니다.

bash
# uv 설치 (macOS. Windows/Linux는 docs.astral.sh/uv 의 설치 안내 참고)
brew install uv

# 프로젝트 생성 & 진입 (02에서 쓴 str | None 문법은 Python 3.10+)
uv init fastapi-hello --python 3.12 && cd fastapi-hello

# 의존성 추가
uv add fastapi "uvicorn[standard]"

첫 엔드포인트

main.py 파일을 만들고 다음을 작성합니다. (전체 예제는 code/main.py에 있습니다.)

python
from fastapi import FastAPI

app = FastAPI()

@app.get("/")
def read_root():
    return {"message": "Hello, FastAPI"}

@app.get("/todos/{todo_id}")
def read_todo(todo_id: int, q: str | None = None):
    return {"todo_id": todo_id, "q": q}

@app.post("/todos", status_code=201)
def create_todo(todo: dict):
    return {"created": todo}

매개변수가 어디서 오는지는 이름과 타입으로 정해집니다. todo_id는 주소에 {todo_id}로 적혀 있으니 경로에서 받고(/todos/42 → 42), 주소에 없는 q는 주소 뒤에 ?q=값으로 붙이는 쿼리 파라미터에서 받습니다(기본값이 None이라 안 붙여도 됩니다). dict 타입인 todo는 요청 본문(body)에 실린 JSON을 받습니다. 이 세 입구는 Week 2에서 자세히 다룹니다.

서버를 띄웁니다:

bash
uv run uvicorn main:app --reload

# main  → main.py 파일
# app   → 그 안의 FastAPI() 인스턴스 변수명
# --reload → 코드 바뀌면 자동 재시작 (개발용)
반환값이 알아서 JSON이 된다. return {"message": "..."}처럼 dict를 반환하면 FastAPI가 그것을 JSON 문자열로 바꾸고(이 변환을 직렬화라고 합니다), "이건 JSON입니다"라는 표시인 Content-Type: application/json 헤더까지 붙여 응답합니다. Express의 res.json(...)을 매번 부를 필요 없이 반환만 하면 끝입니다.
🔄

요청은 어떤 길을 지나는가

주소창에 http://127.0.0.1:8000/todos/42를 치면 내부에서 이런 일이 벌어집니다.

요청은 왼쪽에서 오른쪽으로 세 단계를 지나고, 응답은 한 번에 되돌아온다.
비유 — 호텔 프런트. Uvicorn은 외부 전화를 받아 말을 알아듣는 교환원입니다 — 네트워크로 들어온 HTTP 요청을 Python 앱이 다룰 수 있는 형태로 바꿔 주는 서버이고, 이때 서버와 앱이 대화하는 표준 규격을 ASGI라고 부릅니다. FastAPI는 "42번 방 담당이 누구지?"를 찾아 연결하는 지배인(라우팅)이고, read_todo()가 실제 일을 하는 직원입니다. FastAPI가 내부에서 쓰는 기반 라이브러리 Starlette까지 포함해 셋이 정확히 어떻게 역할을 나누는지는 Week 4에서 해부합니다.
📖

타입 힌트의 보상 — 자동 문서

서버를 띄운 채로 브라우저에서 /docs를 열어보세요. 아무 설정도 안 했는데 인터랙티브 API 문서가 떠 있습니다.

주소무엇특징
/docsSwagger UI브라우저에서 직접 요청을 쏴볼 수 있음 (Try it out)
/redocReDoc읽기 좋은 문서형 레이아웃
/openapi.jsonOpenAPI 명세위 두 화면의 원천 데이터(JSON). 명세(spec) = "어떤 주소에 어떤 입력·출력이 있는지" 적은 설명서

앞에서 todo_id: int라고 적었기 때문에 문서에는 "todo_id는 정수"라고 표시됩니다. 02에서 본 대로 FastAPI가 타입 힌트를 읽어 이 명세를 만든 것입니다(NestJS라면 @ApiProperty를 일일이 달아야 했던 일). 같은 힌트 덕분에 /todos/abc처럼 잘못된 요청은 함수가 실행되기도 전에 422 검증 에러로 막힙니다.

cURL — 터미널에서 API 두드리기

브라우저 없이 API를 테스트하는 가장 기본 도구가 curl입니다. 백엔드 개발자는 이걸 손에 익혀야 합니다.

bash
# GET 요청
curl http://127.0.0.1:8000/todos/42

# 쿼리 파라미터 붙이기
curl "http://127.0.0.1:8000/todos/42?q=hello"

# 헤더 보기 (-i: 응답 헤더 포함)
curl -i http://127.0.0.1:8000/

# POST + JSON 본문 (-X 메서드, -H 헤더, -d 데이터)
curl -X POST http://127.0.0.1:8000/todos \
  -H "Content-Type: application/json" \
  -d '{"title": "장보기", "done": false}'
옵션의미
-XHTTP 메서드 지정 (POST, PATCH …)
-H헤더 추가 (보통 Content-Type)
-d요청 본문(body) 데이터
-i응답에 상태줄·헤더까지 함께 출력
자주 하는 실수. -d로 JSON을 보낼 땐 -H "Content-Type: application/json"을 반드시 붙이세요. curl은 -d만 쓰면 본문을 폼 데이터(HTML <form>이 보내는 key=value&... 형식)라고 표시해서 보내고, 서버는 그 표시를 믿고 JSON으로 읽지 않아 422가 납니다. 그리고 URL에 ?·&가 있으면 셸이 해석하지 않도록 전체를 따옴표로 감싸야 합니다.
✅

셀프 체크

Q uvicorn main:app에서 main과 app은 각각 뭔가요?

"main.py 파일 안의 app이라는 객체를 띄워라"는 뜻입니다. 파일이 server.py이고 변수가 api라면 uvicorn server:api가 됩니다.

Q 설정 한 줄 없이 /docs가 뜨는 이유는?

FastAPI가 경로 함수의 타입 힌트로 /openapi.json을 만들어 두고, /docs는 그 JSON을 화면에 그려 주는 것뿐이기 때문입니다.

Q /todos/abc는 422인데 /todos/42?q=123은 왜 멀쩡한가요?

todo_id는 int라 "abc"를 숫자로 바꿀 수 없어 422입니다. 반면 q는 str | None이고 쿼리 값은 원래 문자열로 들어오니 "123"이라는 문자열 그대로 통과합니다.
