response_model — 나가는 데이터도 검사한다

들어오는 요청만큼 나가는 응답도 중요합니다. response_model은 "이 API는 정확히 이 모양만 돌려준다"를 선언해, 실수로 비밀번호 같은 민감 정보가 새어나가는 것을 막습니다.

한 줄 요약. response_model은 "이 API의 응답은 정확히 이 모양"이라고 미리 정해 두는 것이다. 정해둔 모양에 없는 필드(예: password)는 밖으로 못 나간다. 입력 모델과 출력 모델을 분리하는 것이 실무의 기본기다.

학습 목표

  • response_model로 응답의 형태를 선언하고 필터링한다
  • 입력용·출력용 모델을 분리하는 이유와 패턴을 안다
  • JSONResponse 등 Response 클래스로 응답을 세밀하게 제어한다
🔒

왜 응답에도 모델이 필요한가

회원 정보를 돌려주는 API를 생각해봅시다. DB의 User 객체에는 hashed_password가 들어 있습니다. 해시란 비밀번호를 알아볼 수 없게 한 번 변형해서 저장한 값입니다(원문 비밀번호를 그대로 저장하진 않지만, 그래도 밖으로 나가면 안 되는 값이죠 — 자세한 건 Week 8). 아무 생각 없이 그 객체를 반환하면? 비밀번호 해시가 그대로 클라이언트에 노출됩니다. 끔찍하죠. 아래 예제에서는 단순하게 password라고만 쓰겠습니다 — "나가면 안 되는 필드"라는 점은 같습니다.

비유 — 출국 검색대. 01에서 Pydantic 모델을 입국 심사대(요청 검증)에 비유했죠. 입국 심사대만 있고 출국 검색대가 없으면, 가져가면 안 되는 물건(민감 정보)이 그대로 빠져나갑니다. response_model은 "이 게이트로는 이 목록에 있는 것만 통과"라고 못 박는 출국 검색대입니다. 목록에 없는 password는 자동으로 걸러집니다.
🔀

입력 모델 ≠ 출력 모델

실무의 핵심 패턴: 받을 때(Create)와 돌려줄 때(Public) 모델을 나눕니다. 회원가입을 예로 보죠.

python
from pydantic import BaseModel

# 받을 때: password 포함
class UserCreate(BaseModel):
    username: str
    email: str
    password: str

# 돌려줄 때: password 없음! (id는 추가)
class UserPublic(BaseModel):
    id: int
    username: str
    email: str

이제 라우트에 response_model=UserPublic을 지정합니다. 함수가 비밀번호를 포함한 객체를 반환해도, FastAPI가 UserPublic 모양으로 걸러서 내보냅니다.

python
@app.post("/users", response_model=UserPublic, status_code=201)
def create_user(user: UserCreate):
    saved = {"id": 1, **user.model_dump()}  # id를 붙인 dict (password도 들어 있음)
    return saved
**user.model_dump() — 딕셔너리 풀어 넣기. user.model_dump()는 {"username": ..., "email": ..., "password": ...}라는 dict를 돌려주고, 앞의 **는 "이 dict의 키-값을 바깥 중괄호 안에 하나씩 펼쳐 넣어라"는 뜻입니다. 결과는 {"id": 1, "username": ..., "email": ..., "password": ...} — 서버가 만든 id를 앞에 붙인 새 dict가 됩니다. 실제로는 이 자리에서 DB에 저장하겠지만(Week 5~6), 지금은 저장된 결과를 흉내 낸 것입니다.
response_model이 UserPublic에 없는 password를 걸러낸다.
NestJS — class-transformer
class User {
  id: number;
  @Exclude()        // 직렬화 제외
  password: string;
}

@Exclude + ClassSerializerInterceptor(응답을 내보낼 때 @Exclude를 적용해 주는 인터셉터).

FastAPI — response_model
@app.get(
  "/users/{id}",
  response_model=UserPublic,
)
def get(id): ...

출력 모델을 통째로 선언.

response_model의 3가지 이득. ① 보안 — 민감 필드 자동 제거 · ② 문서 — Swagger에 정확한 응답 스키마 표시 · ③ 검증 — 응답조차 모델에 맞는지 확인합니다. 예를 들어 id를 빠뜨린 채 반환하면 ResponseValidationError가 나며 500 에러로 잡히고, 터미널 로그에 어떤 필드가 빠졌는지 찍히니 개발 중에 바로 알아챌 수 있습니다. 입력 검증만큼 출력 계약도 명확해집니다.
⚙️

유용한 옵션 몇 가지

출력 모델을 새로 만들지 않고, 라우트 데코레이터의 옵션만으로 응답을 살짝 손보는 방법도 있습니다.

옵션효과
response_model_exclude_unset=True값을 넣은 적 없는 필드(기본값만 가진 필드)는 응답에서 생략
response_model_exclude={"email"}특정 필드 제외
response_model_include={"id","username"}특정 필드만 포함

첫 번째 exclude_unset은 조금 미묘해서 예를 보는 게 빠릅니다.

python
class TodoPublic(BaseModel):
    id: int
    title: str
    done: bool = False
    memo: str | None = None

@app.get("/todos/{id}", response_model=TodoPublic, response_model_exclude_unset=True)
def get_todo(id: int):
    return TodoPublic(id=1, title="장보기")
    # 응답: {"id": 1, "title": "장보기"}   ← done·memo는 값을 넣은 적이 없으니 생략
    # 만약 TodoPublic(id=1, title="장보기", done=False)로 만들었다면
    # done=False는 기본값과 같아도 "직접 넣은 값"이라 응답에 포함된다

즉 "설정 안 한"은 기본값과 같다는 뜻이 아니라 값을 넣은 적이 없다는 뜻입니다. 이 구분이 진짜 빛을 보는 곳은 PATCH(부분 수정)입니다 — 클라이언트가 보낸 필드만 골라내 DB에 반영할 때 payload.model_dump(exclude_unset=True)를 쓰는데, Week 6·01에서 실제로 해봅니다.

보통은 출력 모델을 따로 만드는 게 낫습니다. response_model_exclude={"email"} 같은 옵션은 코드만 봐서는 실제 응답 모양을 한눈에 알기 어렵고, Swagger 문서에는 여전히 전체 모델이 표시됩니다. UserPublic처럼 출력 모델을 명시적으로 만드는 게 정석이고, 옵션은 "같은 모델을 딱 한 곳에서만 살짝 다르게 내보낼 때" 정도로만 쓰세요.
📤

Response 클래스 — 응답을 직접 빚기

대부분은 dict나 모델을 반환하면 FastAPI가 알아서 JSON으로 만들어주지만, 가끔 응답 형식·헤더·상태를 직접 제어해야 할 때가 있습니다. 그때 Response 클래스를 씁니다.

클래스용도
JSONResponse기본 JSON 응답 (직접 상태·헤더 제어)
ORJSONResponseorjson(표준 json보다 훨씬 빠른 JSON 라이브러리) 기반 — 대용량에 유리
PlainTextResponse순수 텍스트
RedirectResponse리다이렉트(3xx) — "다른 주소로 가세요"라고 클라이언트를 보내는 응답
StreamingResponse스트리밍 — 응답을 한 번에 다 만들지 않고 조각조각 흘려보냄(대용량 파일·실시간)
python
from fastapi.responses import JSONResponse, RedirectResponse

@app.get("/custom")
def custom():
    return JSONResponse(
        content={"ok": True},
        status_code=200,
        headers={"X-Custom": "hello"},   # 직접 만든 헤더는 관례상 X- 로 시작
    )

@app.get("/old-path")
def moved():
    # 307 = "임시로 옮겼으니 같은 메서드로 저기에 다시 요청하라" (302는 GET으로 바뀔 수 있음)
    return RedirectResponse("/new-path", status_code=307)
Response를 직접 반환하면 response_model이 적용 안 된다. JSONResponse(...)처럼 완성된 Response 객체를 반환하면, FastAPI는 "이미 다 만들었구나" 하고 response_model 필터링·문서 생성을 건너뜁니다. 평소엔 모델/dict를 반환하고, 정말 세밀한 제어가 필요할 때만 Response 클래스를 쓰세요.
✅

셀프 체크

Q 함수가 password를 포함해 반환했는데도 응답에 안 나오는 이유는?

response_model=UserPublic 때문입니다. FastAPI가 반환값을 그 모델 모양으로 다시 만들면서 모델에 없는 필드는 버립니다.

Q 왜 입력 모델(UserCreate)과 출력 모델(UserPublic)을 나누나요?

받는 데이터(password 필요)와 돌려주는 데이터(password 금지, 서버가 만든 id 추가)의 모양이 애초에 다르기 때문입니다.

Q response_model_exclude_unset=True일 때, 기본값과 같은 값을 직접 넣은 필드는 응답에 나오나요?

나옵니다. "설정 안 한"은 값을 넣은 적이 없다는 뜻이지, 기본값과 같다는 뜻이 아닙니다.
