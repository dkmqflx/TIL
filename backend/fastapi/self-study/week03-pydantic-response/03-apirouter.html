APIRouter — 도메인별로 코드를 나누기

모든 라우트를 main.py 하나에 욱여넣으면 금방 수백 줄이 됩니다. APIRouter로 도메인 — "할 일", "회원"처럼 업무 단위로 묶이는 기능 덩어리 — 별로 파일을 나누는 법을 배웁니다.

한 줄 요약. APIRouter는 라우트들을 도메인 단위로 묶는 미니 앱이다. todos 라우터, users 라우터를 따로 만들고 메인 앱에 include_router로 꽂는다. NestJS의 Module/Controller 분리와 같은 발상.

학습 목표

  • APIRouter로 라우트를 도메인별 파일로 분리한다
  • prefix와 tags로 공통 경로·문서 그룹을 지정한다
  • 실무에서 통하는 폴더 구조를 잡는다
🏢

왜 나누는가

비유 — 부서로 나눈 회사. 직원 한 명이 회계·인사·영업을 다 하면 회사가 굴러갈까요? 규모가 커지면 부서(도메인)로 나눕니다. APIRouter는 "할 일 부서(todos)", "회원 부서(users)"처럼 라우트를 갈라 담는 부서 칸막이입니다. 메인 앱은 각 부서를 한데 모으는 본사 역할만 합니다.
🔌

라우터 만들고 꽂기

파일은 이렇게 둡니다. routers/는 도메인별 라우트 파일을 모아 두는 폴더이고, 안에 빈 __init__.py를 두면 파이썬이 이 폴더를 "import할 수 있는 패키지"로 인식합니다.

bash
app/
├── main.py            # ② 라우터를 꽂는 곳
└── routers/           # 폴더 = 패키지
    ├── __init__.py    # 비어 있어도 됨
    ├── todos.py       # ① router 변수를 만드는 곳
    └── users.py

① 도메인별 파일에서 APIRouter를 만들고 라우트를 등록한 뒤, ② main.py에서 include_router로 합칩니다.

python
# routers/todos.py
from fastapi import APIRouter

router = APIRouter(prefix="/todos", tags=["todos"])

@router.get("")          # 실제 경로: GET /todos
def list_todos():
    return [...]

@router.get("/{id}")      # 실제 경로: GET /todos/{id}
def get_todo(id: int):
    return {...}
python
# main.py
from fastapi import FastAPI
from routers import todos, users      # routers 폴더의 todos.py, users.py를 가져온다

app = FastAPI()

app.include_router(todos.router)   # todos.py 안의 router 변수 = 할 일 부서 연결
app.include_router(users.router)   # 회원 부서 연결
prefix와 tags의 역할. prefix="/todos"를 주면 그 라우터의 모든 경로 앞에 /todos가 자동으로 붙습니다 — 라우트마다 반복해서 적을 필요가 없고, 도메인 경로를 한 곳에서 바꿀 수 있죠. tags=["todos"]는 Swagger 문서에서 같은 그룹으로 묶어 보여줍니다. 참고로 prefix는 꽂는 쪽에서 app.include_router(todos.router, prefix="/todos")처럼 줘도 됩니다 — 다른 코드에서 이 형태를 봐도 같은 뜻입니다.
prefix가 있을 때 데코레이터에는 "나머지 경로"만 — 그리고 "" vs "/". prefix가 이미 /todos를 붙여 주므로, 여기에 또 @router.get("/todos")라고 쓰면 경로가 /todos/todos가 됩니다. 그럼 목록 경로는 ""와 "/" 중 뭘 써야 할까요? @router.get("")은 /todos, @router.get("/")은 /todos/(끝 슬래시 포함)로 서로 다른 주소입니다. 한쪽만 등록된 상태에서 다른 쪽으로 요청하면 FastAPI가 기본적으로 307 리다이렉트("같은 메서드로 저 주소에 다시 요청하세요")를 보내 맞는 주소로 안내해 주긴 하지만, 리다이렉트를 따라가지 않는 클라이언트도 있으니 처음부터 하나로 통일하세요. 이 강의는 끝 슬래시 없는 ""로 통일합니다.
🔄

NestJS Module과 나란히

NestJS
@Module({
  controllers: [TodosController],
  providers: [TodosService],
})
export class TodosModule {}

// app.module.ts
@Module({
  imports: [TodosModule, UsersModule],
})
export class AppModule {}
FastAPI
# 각 도메인 = routers/*.py
app.include_router(todos.router)
app.include_router(users.router)

@Module imports ↔ include_router. providers·DI 컨테이너 같은 개념 없이 라우트 함수를 모아 꽂기만 하면 되니 더 가볍고, 어떤 라우터가 붙는지 main.py에 다 보입니다.

실무 폴더 구조

위의 최소 구조에 Pydantic 모델 파일을 더한, 도메인이 늘어날 때 흔히 쓰는 구조입니다.

bash
app/
├── main.py            # FastAPI() 생성 + include_router
├── routers/
│   ├── __init__.py
│   ├── todos.py       # /todos 라우트
│   └── users.py       # /users 라우트
├── schemas.py         # Pydantic 모델 (요청/응답)
└── ...                # Week 5~ DB, 서비스 계층 추가

Pydantic 모델 파일을 models.py가 아니라 schemas.py라고 부르는 데는 이유가 있습니다. 스키마(schema)는 "데이터의 모양 정의"라는 뜻이라 요청/응답 모양을 적는 Pydantic 모델에 딱 맞고, Week 5에서 DB 테이블을 나타내는 SQLAlchemy 클래스가 models.py라는 이름으로 등장하기 때문에, 둘 다 "모델"이라 부르면 헷갈려서 이렇게 나누는 게 관례입니다. 마지막 줄의 서비스 계층은 "라우터는 요청을 받고 응답을 돌려주는 일만 하고, 실제 업무 처리(DB 저장 등)는 별도 파일로 빼는 것"인데, Week 6에서 이 구조 위에 얹습니다.

예고. APIRouter(dependencies=[...])로 라우터 전체에 공통 처리(예: 로그인 확인)를 걸 수도 있습니다 — NestJS의 Guard와 비슷한데, Week 6(Depends)과 Week 8(인증)에서 씁니다.

셀프 체크

Q APIRouter는 NestJS의 무엇에 대응하나요?

도메인별로 라우트를 묶는 Module + Controller 묶음에 대응하고, include_router가 @Module의 imports 역할입니다.

Q @router.get("")과 @router.get("/")는 뭐가 다른가요?

/todos와 /todos/라는 서로 다른 주소입니다. 한쪽만 있으면 307로 안내되긴 하지만, 처음부터 하나로 통일하는 게 안전합니다.

Q 경로가 /todos/todos로 잘못 나옵니다. 원인은?

prefix로 이미 붙은 /todos를 데코레이터에 한 번 더 적었기 때문입니다.
