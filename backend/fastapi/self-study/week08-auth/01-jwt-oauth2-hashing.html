JWT · OAuth2 · 해싱 — “너 누구냐”를 증명하기

로그인은 결국 “이 요청을 누가 보냈는가”를 증명하는 일입니다. 패스워드를 안전하게 보관하고(해싱), 신원을 위조할 수 없는 토큰(JWT)으로 발급하고, 그 토큰을 주고받는 규칙(OAuth2)을 익힙니다.

한 줄 요약. 패스워드는 일방향으로 분쇄(해싱)해서 저장하고, 로그인에 성공하면 서버만 서명할 수 있는 토큰(JWT)을 발급한다. 이후 요청은 그 토큰을 헤더에 실어 보내고, 서버는 서명만 확인하면 “누구인지”를 알 수 있다.

학습 목표

  • 인증(Authentication)과 인가(Authorization)를 구분한다
  • 패스워드를 bcrypt로 해싱·검증하고, 평문·단순 해시 저장이 왜 금지인지 안다
  • JWT의 세 조각(header.payload.signature)과, 누구나 읽을 수 있지만 고칠 수는 없는 이유를 설명한다
  • OAuth2PasswordBearer + /token 엔드포인트로 토큰을 발급하고 Bearer 헤더로 보낸다
🔑

인증 vs 인가 — 헷갈리지 말 것

두 단어가 비슷해 보이지만 묻는 질문이 완전히 다릅니다. 인증이 먼저, 인가가 그 다음입니다.

구분묻는 질문예시
인증 (Authentication)“너 누구냐?”아이디·비밀번호 로그인, 토큰 검증
인가 (Authorization)“너 이거 할 권한 있냐?”관리자만 삭제 가능, 본인 글만 수정
비유 — 공연장 입장. 인증은 입구에서 신분증을 확인하고 입장 팔찌를 채워주는 일입니다(너 누구냐). 인가는 그 팔찌 색깔을 보고 “일반석은 되지만 백스테이지는 안 됨”을 판정하는 일이죠(권한 있냐). 이번 레슨은 인증과 팔찌(JWT) 발급, 다음 레슨은 인가를 다룹니다.
🔒

패스워드 해싱 — 절대 평문 저장 금지

DB가 유출되는 사고는 언제든 일어납니다. 그때 패스워드가 평문으로 들어 있으면 모든 사용자 계정이 그 즉시 털립니다. 그래서 패스워드는 원본을 복구할 수 없는 형태로 변환해 저장합니다 — 이게 해싱입니다.

비유 — 일방향 분쇄기. 해싱은 종이(평문 비밀번호)를 분쇄기에 넣는 것과 같습니다. 같은 종이를 넣으면 늘 같은 조각 패턴(해시)이 나오지만, 조각을 보고 원래 종이를 복원할 수는 없습니다. 로그인 때는 “들어온 비밀번호를 똑같이 분쇄해서, 저장된 조각과 일치하는가”만 비교합니다. 서버조차 원본 비밀번호를 모르는 게 정상입니다.

실무 표준은 bcrypt입니다. 파이썬에선 pwdlib[bcrypt](FastAPI 공식 문서가 채택)로 씁니다. 핵심 동작은 두 가지 — hash(가입할 때 저장용)와 verify(로그인할 때 비교용)입니다.

python
from pwdlib import PasswordHash
from pwdlib.hashers.bcrypt import BcryptHasher

password_hash = PasswordHash((BcryptHasher(),))

def hash_password(raw: str) -> str:
    return password_hash.hash(raw)            # 가입 시 1회 — 이 결과만 DB에 저장

def verify_password(raw: str, hashed: str) -> bool:
    return password_hash.verify(raw, hashed)  # 로그인 시 — 일치 여부만 반환
pwdlib vs passlib. 예전 자료엔 passlib가 많이 보이는데, API는 거의 같지만 passlib(1.7.4)는 최신 bcrypt 패키지(5.x)와 충돌해 에러가 나는 경우가 있습니다. 새 프로젝트와 이 스터디의 실행 예제(code/main.py)는 pwdlib를 씁니다.
평문·MD5·SHA256 단독 저장은 모두 금지. sha256(password) 같은 단순 해시는 원래 “빨리 계산하라”고 만든 함수라서, 공격자도 초당 수십억 개의 비밀번호 후보를 해시해 보며 맞춰볼 수 있습니다(무차별 대입 — 될 때까지 다 찔러보기). 흔한 비밀번호의 해시를 미리 계산해 둔 표(레인보우 테이블)와 대조하면 더 빠르죠. bcrypt는 이 두 공격을 막도록 설계된 비밀번호 전용 알고리즘입니다 — 일부러 느리게 계산하고(한 번에 수십 ms, 공격자는 수십억 번이 수십 년이 됨), 해시할 때마다 무작위 값(솔트)을 섞어 같은 비밀번호라도 결과가 매번 달라 미리 만든 표가 무용지물이 됩니다. 솔트는 해시 문자열 안에 함께 저장되니 따로 관리할 필요가 없습니다. 비밀번호엔 반드시 bcrypt / argon2를 쓰세요.
bcrypt의 72바이트 제한. bcrypt는 입력의 앞 72바이트까지만 보며, 최신 bcrypt 5.x는 그보다 길면 아예 오류를 냅니다. “왜 긴 비밀번호가 안 먹지?”의 원인이 이것이니, 실무에선 입력 길이를 제한하거나(예: 64자) 제한이 없는 argon2를 씁니다.

JWT — 위조 방지 입장 팔찌

로그인에 성공하면 서버는 JWT(JSON Web Token)를 발급합니다. 생김새는 점(.) 두 개로 나뉜 한 줄짜리 긴 문자열입니다.

bash
eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiLrr7zsiJgiLCJleHAiOjE3MzB9.dQw4w9WgXcQ
└──── header ────┘ └────────── payload ──────────┘ └─ signature ─┘
조각무엇이 들었나
header서명 방식 이름. 예: HS256 = “비밀키 하나로 도장을 찍고, 같은 비밀키로 확인한다”
payload담고 싶은 정보(클레임이라 부름). 보통 sub(누구인지 — 사용자 식별자)와 exp(언제 만료되는지)
signatureheader + payload + 서버만 아는 비밀키를 섞어 계산한 짧은 값 — 서버의 도장

세 조각을 순서대로 따라가 봅시다. ① header와 payload는 그냥 JSON을 base64로 바꿔 쓴 것입니다. base64는 암호화가 아니라 “글자를 다른 글자로 바꿔 적는 규칙”(인코딩)이라, 누구나 원래대로 되돌려 읽을 수 있습니다. 그래서 payload엔 비밀번호·카드번호 같은 민감 정보를 절대 넣지 않고, 공개돼도 괜찮은 최소한(sub, exp)만 담습니다.

② signature가 핵심입니다. 서버는 header와 payload의 내용에 자기만 아는 비밀키(SECRET_KEY)를 섞어 짧은 값을 계산합니다 — 쉽게 말해 서버만 찍을 수 있는 도장입니다. 누군가 payload의 sub를 다른 사람으로 고치면 내용이 달라졌으니 기존 도장과 맞지 않게 되고, 새로 도장을 찍으려면 비밀키가 필요한데 그건 서버만 갖고 있습니다. 그래서 JWT는 읽을 수는 있지만 고칠 수는 없습니다. 서버는 매 요청마다 “도장이 맞는가”만 확인하면 누가 보냈는지 믿을 수 있고, 로그인한 사람 명단을 따로 들고 있을 필요가 없습니다.

비유 — 위조 방지 입장 팔찌. 위에서 입구 직원이 채워준 팔찌가 바로 JWT입니다. 팔찌엔 좌석 정보(payload)가 적혀 있어 누구나 읽을 수 있지만, 주최 측만 가진 특수 인장(signature)이 찍혀 있어서 손님이 좌석을 VIP로 고쳐 쓰면 인장이 깨져 바로 들킵니다.

코드로는 발급이 jwt.encode, 검증이 jwt.decode입니다. 둘 다 같은 SECRET_KEY를 씁니다.

python
import jwt
from datetime import datetime, timedelta, timezone

SECRET_KEY = "..."           # 프로덕션에선 환경변수/시크릿. 절대 커밋 금지!
ALGORITHM = "HS256"

def create_access_token(sub: str) -> str:
    payload = {
        "sub": sub,                                       # 누구인지
        "exp": datetime.now(timezone.utc) + timedelta(minutes=30),  # 만료
    }
    return jwt.encode(payload, SECRET_KEY, algorithm=ALGORITHM)

def decode_token(token: str) -> dict:
    # 서명이 깨졌거나 exp 가 지났으면 예외 발생
    return jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
exp(만료)는 반드시 넣는다. 토큰은 한 번 발급하면 되돌릴 수 없으니, 유출돼도 피해가 짧게 끝나도록 수명을 짧게 둡니다(예: 30분). jwt.decode는 exp가 지난 토큰을 자동으로 거부합니다(PyJWT는 ExpiredSignatureError). 그렇다고 30분마다 다시 로그인시킬 순 없으니, 실무에선 refresh 토큰을 같이 씁니다 — 수명이 긴(예: 2주) 별도 토큰을 서버가 따로 저장해 두고, access 토큰이 만료되면 새 access 토큰을 받아오는 용도로만 쓰는 것입니다. access 토큰은 짧게 유지하면서도 사용자는 로그인을 유지할 수 있습니다.

OAuth2PasswordBearer + /token

OAuth2는 “토큰으로 인증하는 방법”을 정해 둔 표준 규격입니다. 그중 가장 단순한 것이 Password Flow — 아이디·비밀번호를 직접 내고 토큰을 받는 흐름입니다(구글 로그인 같은 건 다른 flow). 토큰은 Authorization: Bearer <토큰> 헤더로 보내는데, Bearer는 “소지자”라는 뜻으로 이 토큰을 가진 사람을 주인으로 인정한다는 말입니다. 그래서 토큰은 비밀번호처럼 다뤄야 합니다.

FastAPI는 이 흐름에 맞는 부품 두 개를 제공합니다.

부품역할
OAuth2PasswordRequestForm/token이 받을 username/password 폼을 정의
OAuth2PasswordBearer보호된 요청에서 Authorization: Bearer ... 헤더의 토큰을 꺼내옴 + Swagger에 자물쇠 버튼을 자동으로 추가
python
from fastapi import APIRouter, Depends, HTTPException
from fastapi.security import OAuth2PasswordRequestForm, OAuth2PasswordBearer

# tokenUrl: Swagger UI 에 "로그인은 /token 으로" 알려주는 용도
oauth2_scheme = OAuth2PasswordBearer(tokenUrl="token")
router = APIRouter()

@router.post("/token")
def login(form: OAuth2PasswordRequestForm = Depends()):
    # 인자 없는 Depends() = 타입 힌트의 클래스를 그대로 의존성으로 사용
    user = get_user(form.username)            # DB 조회 함수(직접 작성)
    if not user or not verify_password(form.password, user.hashed):
        raise HTTPException(401, "아이디 또는 비밀번호가 틀렸습니다")
    token = create_access_token(sub=user.username)
    return {"access_token": token, "token_type": "bearer"}

user.hashed는 가입 때 hash_password로 만들어 저장해 둔 해시입니다. 응답 모양(access_token + token_type)은 OAuth2 규격이 정한 것이라 Swagger UI가 그대로 알아듣습니다.

라이브러리 선택 — 한 가지로 통일. JWT 라이브러리는 PyJWT(import jwt)와 python-jose(from jose import jwt)가 있는데, 이 스터디는 가볍고 유지보수가 활발한 PyJWT로 통일합니다. 예외 클래스가 다르니 섞지 마세요(PyJWT: jwt.ExpiredSignatureError / jwt.InvalidTokenError, jose: JWTError).
python-multipart이 필요하다. OAuth2PasswordRequestForm은 JSON이 아니라 폼 데이터를 읽기 때문에, python-multipart 패키지가 없으면 /token 호출 시 RuntimeError가 납니다. 설치 목록에 꼭 포함하세요.
🔄

전체 흐름 — 로그인 → 토큰 → Bearer 요청

지금까지의 부품을 한 장면으로 이어 보면 이렇습니다. 로그인(①②)은 딱 한 번이고, 그 뒤로는 모든 요청(③④)이 토큰만 들고 다닙니다. ③의 /me는 “토큰이 있어야 들어갈 수 있는 라우트”의 예시로, 다음 레슨에서 직접 만듭니다.

한 번 로그인해 토큰을 받으면, 이후 요청은 토큰만 헤더에 실어 보낸다.

NestJS와 비교 — Passport가 없다는 것의 의미

NestJS에서 JWT 인증을 붙이려면 JwtModule.register(), PassportStrategy를 상속한 JwtStrategy, AuthGuard('jwt')… 파일 서너 개를 오간 뒤에야 req.user가 채워졌죠. FastAPI에는 Passport 같은 인증 프레임워크가 아예 없습니다. OAuth2PasswordBearer는 “헤더에서 토큰 문자열 꺼내기” 한 가지만 하고, “이 토큰이 진짜인가, 어떤 유저인가”는 여러분이 쓰는 열 줄짜리 함수가 담당합니다.

비유 — 완제품 가구 vs 부품 키트. Passport는 조립된 붙박이장입니다. 튼튼하지만 서랍 하나를 바꾸려면 설계도(전략 클래스, 가드, validate()…)를 뒤져야 하죠. FastAPI는 부품 키트입니다. 나사(jwt.decode)와 손잡이(OAuth2PasswordBearer)를 직접 조립하니 처음엔 손이 가지만, 어디에 무엇이 들었는지 전부 보여 디버깅과 변형이 쉽습니다.
NestJS — @nestjs/jwt + bcrypt
// 발급
const token = await this.jwt
  .signAsync({ sub: user.id });
// 만료는 모듈 설정에서
// signOptions.expiresIn: '30m'

// 해싱
const hash =
  await bcrypt.hash(pw, 12);
const ok = await bcrypt
  .compare(pw, hash);
FastAPI — PyJWT + pwdlib
# 위에서 직접 만든 함수 그대로
token = create_access_token(uid)
# exp 는 이 함수 안에서 직접 넣음

hashed = hash_password(pw)
ok = verify_password(pw, hashed)
NestJSFastAPI (이번 강의)
bcrypt.hash() / bcrypt.compare()hash_password() / verify_password()
JwtModule.register({ secret })SECRET_KEY 상수(환경변수)
jwtService.signAsync(payload)jwt.encode(payload, SECRET_KEY, algorithm=...)
JwtStrategy + ExtractJwt.fromAuthHeaderAsBearerToken()OAuth2PasswordBearer(tokenUrl="token")
strategy.validate() + @UseGuards(AuthGuard('jwt'))get_current_user 의존성 + Depends(...) (다음 레슨)
만료(exp)를 잊기 쉽다. NestJS에선 expiresIn: '30m'을 모듈 설정에 한 번 써두면 끝이었지만, FastAPI에선 토큰을 만들 때마다 payload에 exp를 직접 넣어야 합니다. 빼먹으면 영원히 만료되지 않는 토큰이 나갑니다. 토큰 생성 함수를 create_access_token 하나로 모아두고 그 안에서만 만드세요.

셀프 체크

Q 인증과 인가의 차이를 한 문장으로?

인증은 “너 누구냐”(신원 확인), 인가는 “너 이거 할 권한 있냐”(권한 확인)입니다. 인증이 먼저 끝나야 인가를 따질 수 있습니다.

Q 패스워드를 sha256으로 해시해서 저장하면 안 되나요?

안 됩니다. sha256은 빠르게 계산하라고 만든 함수라 공격자도 후보를 초당 수십억 개씩 시험할 수 있습니다. 비밀번호엔 일부러 느리고 솔트를 섞는 bcrypt/argon2를 씁니다.

Q JWT payload에 사용자 비밀번호를 넣어도 되나요?

안 됩니다. payload는 글자만 바꿔 쓴 것(base64)이라 토큰을 손에 넣은 누구나 펼쳐 볼 수 있습니다. 서명은 “고쳤는지”를 잡아낼 뿐, 내용을 감춰 주지는 않습니다.
