TypeORM에서 데이터는 Entity 클래스로 정의하고, Repository를 통해 DB와 통신합니다.

Raw SQL vs TypeORM

TypeORM은 객체와 관계형 DB를 매핑하는 ORM입니다. SQL을 직접 쓰지 않고 TypeScript 객체로 DB를 다룰 수 있게 해줍니다.

❌ Raw SQL (직접 작성)
// 반복적인 코드, SQL 의존적
const result = await dataSource.query(
  `INSERT INTO categories (name) VALUES ($1)
   RETURNING id`,
  [category.name]
);
const id = result[0].id;
✅ TypeORM (객체 중심)
// 간결하고 객체 지향적
const saved = await this.categoryRepository
  .save(category);
const id = saved.id;

핵심 개념 4가지

🗂️
Entity
DB 테이블과 매핑되는 TypeScript 클래스. @Entity() 데코레이터로 선언.
🔌
Repository
Entity에 대한 CRUD 작업을 담당. Repository<T> 타입으로 주입.
💾
DataSource
DB 연결 설정의 중심. 트랜잭션·마이그레이션 실행의 진입점.
⚡
주의: save() 필수
엔티티를 변경해도 save()를 호출해야 DB에 반영됩니다. 변경 사항이 자동으로 저장되지 않습니다.

bash

app.module.ts

typescript
import { TypeOrmModule } from '@nestjs/typeorm';

@Module({
  imports: [
    TypeOrmModule.forRoot({
      type: 'postgres',
      host: process.env.DB_HOST,
      port: Number(process.env.DB_PORT) || 5432,
      username: process.env.DB_USERNAME,
      password: process.env.DB_PASSWORD,
      database: process.env.DB_NAME,
      entities: [__dirname + '/**/*.entity{.ts,.js}'],
      synchronize: true,  // 개발 환경에서만 사용 (프로덕션은 false)
    }),
  ],
})
export class AppModule {}
synchronize: true는 Entity 변경 시 DB 스키마를 자동으로 업데이트합니다. 프로덕션에서는 반드시 false로 설정하고 마이그레이션을 사용하세요.

Entity 정의

TypeORM에서 테이블 구조는 Entity 클래스로 정의합니다.

typescript
// user.entity.ts
import {
  Entity,
  PrimaryGeneratedColumn,
  Column,
  CreateDateColumn,
  UpdateDateColumn,
} from 'typeorm';

@Entity('users')
export class User {
  @PrimaryGeneratedColumn()
  id: number;

  @Column({ length: 50 })
  name: string;

  @Column({ unique: true })
  email: string;

  @Column()
  age: number;

  @CreateDateColumn({ name: 'created_at' })
  createdAt: Date;

  @UpdateDateColumn({ name: 'updated_at' })
  updatedAt: Date;
}

자주 쓰는 컬럼 데코레이터

데코레이터설명
@PrimaryGeneratedColumn()AUTO_INCREMENT PK
@PrimaryGeneratedColumn('uuid')UUID PK
@Column()일반 컬럼
@Column({ nullable: true })NULL 허용
@Column({ unique: true })UNIQUE 제약
@Column({ default: 0 })기본값 설정
@CreateDateColumn()INSERT 시 자동 설정
@UpdateDateColumn()UPDATE 시 자동 갱신
@VersionColumn()낙관적 락 버전 관리 (Part 5)

AUTO_INCREMENT vs UUID — 어떤 PK를 써야 할까?

두 방식은 PK를 어떤 값으로, 누가 만드느냐가 다릅니다.

@PrimaryGeneratedColumn() — AUTO_INCREMENT
@Entity()
export class User {
  @PrimaryGeneratedColumn()
  id: number;  // 1, 2, 3, ...

  @Column()
  name: string;
}
DB에 저장되는 모습

@PrimaryGeneratedColumn('uuid') — UUID
@Entity()
export class User {
  @PrimaryGeneratedColumn('uuid')
  id: string;  // '550e8400-e29b-...'

  @Column()
  name: string;
}

AUTO_INCREMENTUUID
타입numberstring
생성 주체DB가 순서대로 부여앱(또는 DB)이 무작위 생성
예측 가능성/users/3으로 총 사용자 수 유추 가능무작위값이라 유추 불가
JOIN 성능빠름 (int 비교)상대적으로 느림 (string 비교)
분산 시스템여러 DB 인스턴스 간 충돌 위험충돌 없음
적합한 상황단일 DB, 내부 참조용 테이블외부 노출 리소스, 마이크로서비스
실무 패턴 — 두 가지를 함께 사용하기
내부 JOIN 성능은 AUTO_INCREMENT로, 외부 노출 URL은 UUID로 분리하면 두 장점을 모두 얻을 수 있습니다. 
@Entity()
export class User {
  @PrimaryGeneratedColumn()
  id: number;          // 내부 JOIN용 — 빠른 int 비교

  @Column({ unique: true, default: () => 'gen_random_uuid()' })
  publicId: string;    // 외부 노출용 — URL에 사용 (/users/550e8400-...)
}
테이블 간 관계를 표현하는 @ManyToOne, @OneToMany, @ManyToMany 같은 연관관계 데코레이터는 Part 3 · 연관관계 매핑에서 자세히 다룹니다.

Setter 대신 메서드 사용

TypeScript에서도 public setter 남용은 데이터 무결성을 해칩니다. 의미 있는 메서드로 대체하세요.

❌ 나쁜 예 — public setter
@Entity()
export class Post {
  @Column()
  title: string;

  // 어디서든 마음대로 변경 가능
  setTitle(title: string) {
    this.title = title; // 빈 문자열? null?
  }
}

// 호출부
post.setTitle('');    // 빈 제목?
post.setTitle(null);  // null?
✅ 좋은 예 — 의미 있는 메서드
@Entity()
export class Post {
  @Column({ nullable: false })
  title: string;

  // 비즈니스 로직이 명확
  updateTitle(newTitle: string): void {
    if (!newTitle?.trim()) {
      throw new BadRequestException(
        '제목은 필수입니다.'
      );
    }
    if (newTitle.length > 100) {
      throw new BadRequestException(
        '제목은 100자를 초과할 수 없습니다.'
      );
    }
    this.title = newTitle;
  }
}
장점: 유효성 검증이 Entity 안에 모임 → 어디서 호출해도 일관된 규칙이 적용됩니다. Controller/Service에서 중복 검증이 필요 없어집니다.

typescript

@Module({
  imports: [TypeOrmModule.forFeature([User])],
  providers: [UsersService],
  controllers: [UsersController],
})
export class UsersModule {}

Repository 주입

typescript
@Injectable()
export class UsersService {
  constructor(
    @InjectRepository(User)
    private readonly userRepository: Repository<User>,
  ) {}
}
