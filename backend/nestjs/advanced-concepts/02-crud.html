find - 데이터 조회 GET

전체 조회

typescript
// SELECT * FROM users
const users = await this.userRepository.find();

조건 조회

typescript
// SELECT * FROM users WHERE id = 1 LIMIT 1
const user = await this.userRepository.findOne({ where: { id: 1 } });

// SELECT * FROM users WHERE age >= 30
const users = await this.userRepository.find({
  where: { age: MoreThanOrEqual(30) },
});
프론트 관점에서: GET /users/1 요청이 내부적으로 findOne({ where: { id: 1 } })처럼 동작합니다.

TypeORM 비교 연산자

typescript
import { Equal, Not, LessThan, MoreThanOrEqual, Like, In, IsNull } from 'typeorm';

find({ where: { age: LessThan(20) } })           // WHERE age < 20
find({ where: { name: Like('김%') } })            // WHERE name LIKE '김%'
find({ where: { id: In([1, 2, 3]) } })           // WHERE id IN (1, 2, 3)
find({ where: { email: IsNull() } })             // WHERE email IS NULL
find({ where: { email: Not(IsNull()) } })        // WHERE email IS NOT NULL

정렬 / 특정 컬럼 선택

typescript
// ORDER BY age DESC
find({ order: { age: 'DESC' } })

// SELECT name, email FROM users
find({ select: { name: true, email: true } })

// ORDER BY + WHERE 조합
find({
  where: { age: MoreThanOrEqual(20) },
  order: { createdAt: 'DESC' },
  select: { id: true, name: true, email: true },
})

save - 데이터 삽입 POST

단건 삽입

typescript
// INSERT INTO users (name, email, age) VALUES ('홍길동', 'hong@example.com', 27)
const user = this.userRepository.create({
  name: '홍길동',
  email: 'hong@example.com',
  age: 27,
});

const saved = await this.userRepository.save(user);
console.log(saved.id); // 자동 생성된 PK
create()는 Entity 인스턴스를 생성(메모리)하고, save()가 실제 DB에 저장합니다. Spring JDBC의 KeyHolder와 달리 saved.id로 바로 접근 가능합니다.

DTO와 함께 사용 (실무 패턴)

typescript
// create-user.dto.ts
export class CreateUserDto {
  name: string;
  email: string;
  age: number;
}

// service
async create(dto: CreateUserDto): Promise<User> {
  const user = this.userRepository.create(dto);
  return this.userRepository.save(user);
}

update / save - 데이터 수정 PATCH

방법 1: update() — 부분 수정
엔티티를 조회하지 않고 바로 수정. 빠르지만 affected 확인 필요.
방법 2: save() — 전체 수정
findOne() 후 수정. 존재 여부를 자동 확인할 수 있음.

방법 1: update()

typescript
// UPDATE users SET email = 'new@example.com' WHERE id = 1
const result = await this.userRepository.update(1, { email: 'new@example.com' });

if (result.affected === 0) {
  throw new NotFoundException('수정할 데이터가 없습니다.');
}

방법 2: save() (findOne 후 수정)

typescript
const user = await this.userRepository.findOne({ where: { id: 1 } });
if (!user) throw new NotFoundException('사용자를 찾을 수 없습니다.');

user.name = '김철수';
user.email = 'kim@example.com';
user.age = 29;

await this.userRepository.save(user);
update()save() — findOne 후
DB 쿼리 수1번 (UPDATE만)2번 (SELECT → UPDATE)
존재 여부 확인result.affected로 간접 확인findOne()에서 직접 확인
라이프사이클 훅❌ @BeforeUpdate 등 발동 안 됨✅ 발동됨
비즈니스 로직 적용어려움 (엔티티 객체 없음)용이 (객체를 직접 다룰 수 있음)
적합한 상황단순 필드 패치, 관리자 일괄 수정서비스 계층의 일반적인 수정 로직
실무 선택 기준
• 특정 필드만 빠르게 변경하면 되고 훅·검증이 필요 없다면 → update(id, { field })
• 수정 전에 데이터를 가져와 비즈니스 로직을 적용하거나, 수정된 결과를 응답으로 반환해야 한다면 → findOne() 후 save()
대부분의 서비스 계층 코드는 save() 방식을 씁니다. findOne()에서 존재 확인 + 예외 처리를 동시에 할 수 있어 코드가 명확합니다.

delete / remove - 데이터 삭제 DELETE

TypeORM에는 삭제 방법이 두 가지입니다. 가장 큰 차이는 "DB에서 먼저 조회하느냐"입니다.

delete()remove()
DB 조회 필요 여부❌ 없음 (빠름)✅ 먼저 findOne() 필요
존재 여부 확인result.affected로 확인findOne()에서 직접 확인
cascade 이벤트 발동❌ 발동 안 됨✅ @BeforeRemove 등 발동
언제 사용단순 삭제 (ID로 바로 삭제)삭제 전 엔티티 검증·가공이 필요할 때

방법 1: delete() — ID(조건)로 바로 삭제

DB에서 먼저 조회하지 않고 조건만으로 DELETE를 실행합니다. DB 요청이 1번이라 빠릅니다.

typescript
// DB 요청: 1번
// DELETE FROM users WHERE id = 1
const result = await this.userRepository.delete(1);
// ※ id 대신 조건 객체도 가능: delete({ email: 'test@test.com' })

// affected: 실제로 삭제된 행 수
// 삭제할 데이터가 애초에 없었다면 affected === 0
if (result.affected === 0) {
  throw new NotFoundException('삭제할 데이터가 없습니다.');
}

// delete()는 삭제된 엔티티 객체를 반환하지 않음
// → 삭제 후 해당 데이터가 필요하면 remove()를 써야 함

방법 2: remove() — 엔티티 객체를 받아 삭제

먼저 엔티티를 조회한 뒤, 그 객체를 넘겨서 삭제합니다. DB 요청이 2번(조회 + 삭제)입니다.

typescript
// DB 요청: 2번 (SELECT → DELETE)

// 1) 먼저 조회 — 없으면 여기서 예외를 던짐
const user = await this.userRepository.findOne({ where: { id: 1 } });
if (!user) throw new NotFoundException();

// 2) 조회한 엔티티 객체를 넘겨서 삭제
// DELETE FROM users WHERE id = 1
await this.userRepository.remove(user);

// remove()의 장점: 삭제 전 user 객체를 코드에서 활용 가능
// 예) 삭제 전에 user.name을 로그로 남기거나, 응답으로 반환하거나
실무 선택 기준
• 단순히 "ID로 삭제"만 하면 된다면 → delete(id) (더 빠름)
• 삭제 전에 권한 확인, 로그 기록, 또는 삭제된 데이터를 응답으로 반환해야 한다면 → findOne() 후 remove()
조건 없이 delete({})를 호출하면 테이블 전체가 삭제됩니다. WHERE 조건을 반드시 확인하세요.
🗃️

softDelete — 실무에서 가장 많이 쓰는 삭제 패턴 DELETE

실무에서는 데이터를 DB에서 실제로 지우지 않는 경우가 많습니다. 삭제된 시각만 기록해 두고 조회 시 자동으로 걸러내는 Soft Delete 패턴을 씁니다.

Hard Delete (delete/remove)Soft Delete (softDelete)
실제 삭제 여부DB에서 행 자체를 제거행은 남기고 deleted_at 컬럼에 시각 기록
복구 가능 여부❌ 불가능✅ restore()로 복구 가능
감사 로그 / 규정 준수이력 추적 어려움삭제 시각·삭제자 이력 남김
적합한 상황임시 데이터, 캐시, 로그 정리사용자 데이터, 주문, 게시글 등 핵심 도메인

1단계 — 엔티티에 @DeleteDateColumn 추가

@DeleteDateColumn을 선언하면 TypeORM이 softDelete() 호출 시 자동으로 해당 컬럼에 시각을 기록하고, 이후 find() 쿼리에서 자동으로 제외합니다.

typescript
@Entity()
export class User {
  @PrimaryGeneratedColumn()
  id: number;

  @Column()
  name: string;

  @CreateDateColumn({ name: 'created_at' })
  createdAt: Date;

  // 이 컬럼 하나로 Soft Delete 활성화
  @DeleteDateColumn({ name: 'deleted_at', nullable: true })
  deletedAt: Date | null;  // 삭제 전: null / 삭제 후: 삭제된 시각
}

2단계 — softDelete / restore 사용

typescript
// ── 삭제 (deleted_at에 현재 시각 기록, 행은 남아 있음) ──
// UPDATE users SET deleted_at = NOW() WHERE id = 1
await this.userRepository.softDelete(1);

// ── 복구 (deleted_at을 다시 null로) ──
// UPDATE users SET deleted_at = NULL WHERE id = 1
await this.userRepository.restore(1);

// ── 일반 조회 — 소프트 삭제된 행은 자동으로 제외됨 ──
// SELECT * FROM users WHERE deleted_at IS NULL
const users = await this.userRepository.find();

// ── 소프트 삭제된 항목까지 포함해서 조회 ──
const allUsers = await this.userRepository.find({ withDeleted: true });

실무에서의 전체 흐름 예시

typescript
// user.service.ts
async remove(id: number): Promise {
  // 1) 존재 확인 (없으면 404)
  const user = await this.userRepository.findOne({ where: { id } });
  if (!user) throw new NotFoundException('사용자를 찾을 수 없습니다.');

  // 2) Soft Delete — DB에서 지우지 않고 deleted_at만 기록
  await this.userRepository.softDelete(id);
}

async restore(id: number): Promise {
  const result = await this.userRepository.restore(id);
  if (result.affected === 0) {
    throw new NotFoundException('복구할 데이터가 없습니다.');
  }
}
update / delete / remove / softDelete — 실무 의사결정 요약
메서드DB 쿼리언제 쓰나
update(id, dto)UPDATE 1번단순 필드 패치. 빠르게 변경만 하면 될 때
findOne() + save()SELECT + UPDATE 2번서비스 계층의 일반적인 수정. 비즈니스 로직·훅이 필요할 때 (가장 흔함)
delete(id)DELETE 1번단순 물리 삭제. 임시 데이터·관리자 일괄 삭제
findOne() + remove()SELECT + DELETE 2번삭제 전 엔티티 활용 필요. @BeforeRemove 훅 트리거
softDelete(id)UPDATE 1번핵심 도메인 데이터 삭제. 복구·이력이 필요할 때 (실무 표준)
