Config · 파일 업로드 · Static 환경 변수부터 URL 제공까지

ConfigModule로 .env를 읽고, Multer로 파일을 서버에 저장하고, ServeStaticModule로 업로드한 파일을 URL로 제공하는 세 단계를 이어붙인다.

한 줄 요약. 환경 변수는 코드 밖에, 파일은 서버 디스크에, URL은 정해진 경로로. 세 모듈을 연결하면 이미지 업로드 → 저장 → URL 응답이 한 흐름으로 완성된다.

학습 목표

  • ConfigModule.forRoot({ isGlobal: true })로 전역 환경 변수를 설정하고 ConfigService.get()으로 값을 읽을 수 있다
  • @UseInterceptors(FileInterceptor('image'))와 @UploadedFile()로 멀티파트 파일을 수신한다
  • ServeStaticModule.forRoot({ rootPath, serveRoot })로 업로드 파일을 특정 URL 경로로 제공한다
⚙️

ConfigModule — .env 읽기

개발 중인 내 컴퓨터는 로컬 DB를 보고, 운영 서버는 클라우드 DB를 봅니다. 포트 번호도, JWT 시크릿도 환경마다 다릅니다. 이런 값을 const PORT = 3000처럼 코드 안에 직접 적어두면(하드코딩), 환경이 바뀔 때마다 코드를 고치고 다시 빌드해야 하고, 무엇보다 DB 비밀번호 같은 민감한 값이 소스코드 그대로 저장소에 남게 됩니다. @nestjs/config의 ConfigModule은 이런 값들을 코드 밖, .env라는 파일로 떼어놓고, 코드는 그저 "이 키의 값을 읽어와라"라고만 요청하도록 만들어 줍니다.

비유 — 체인점의 지점별 설정표. 커피 체인은 모든 지점이 같은 레시피(코드)를 씁니다. 하지만 지점 전화번호, 원두 납품업체, 결제 단말기 코드처럼 지점마다 다른 값도 있습니다. 이런 값을 레시피북 자체에 적어두고 매장마다 다시 인쇄하는 대신, 계산대 옆에 걸린 지점 설정표 한 장에 적어두면 됩니다. 직원은 필요할 때 그 표를 펼쳐보기만 하면 되고, 레시피는 손댈 필요가 없습니다. .env가 이 설정표이고, ConfigService.get('KEY')가 표를 펼쳐보는 동작입니다.

등록 방법은 루트 모듈에서 ConfigModule.forRoot()를 한 번 호출하는 것으로 끝입니다. isGlobal: true를 주면 다른 모듈은 매번 imports에 ConfigModule을 추가하지 않아도, 어디서든 ConfigService를 주입받아 곧바로 쓸 수 있습니다.

typescriptapp.module.ts — ConfigModule 전역 등록
import { Module } from '@nestjs/common';
import { ConfigModule } from '@nestjs/config';

@Module({
  imports: [
    ConfigModule.forRoot({
      isGlobal: true,   // 모든 모듈에서 imports 없이 사용 가능
      envFilePath: '.env',
    }),
  ],
})
export class AppModule {}
typescriptsome.service.ts — ConfigService로 값 읽기
import { Injectable } from '@nestjs/common';
import { ConfigService } from '@nestjs/config';

@Injectable()
export class SomeService {
  constructor(private readonly configService: ConfigService) {}

  getPort(): number {
    return this.configService.get<number>('PORT') ?? 3000;
  }
}

?? 3000처럼 기본값을 함께 적어 두면, .env에 PORT가 없거나 파일 자체가 빠져 있어도 앱이 기본 포트로 조용히 뜹니다. 값이 없다고 앱이 죽어버리는 것보다, 개발 환경에서는 이런 안전장치가 훨씬 편합니다.

.env는 절대 커밋하지 않는다. .env에는 DB 비밀번호, JWT 시크릿, AWS 키 같은 민감 정보가 담깁니다. 반드시 .gitignore에 추가하고, 팀원 공유는 별도 보안 채널(Vault, AWS Secrets Manager)을 이용하세요. 레포에 커밋하면 이미 유출입니다.

파일 업로드 — Multer + FileInterceptor

지금까지 다룬 요청 바디는 전부 JSON이었습니다. JSON은 순수 텍스트라서 JSON.parse() 한 번이면 객체로 바뀝니다. 하지만 이미지·동영상 같은 파일은 텍스트가 아닌 바이너리 데이터이고, 폼에 텍스트 필드와 파일이 함께 올라오기도 합니다. 이런 요청은 Content-Type: multipart/form-data로 전송되는데, 이 형식은 일반 JSON 파서로는 읽을 수 없어 별도의 파서가 필요합니다.

비유 — 편지와 소포는 접수 창구가 다르다. 우체국에서 편지(JSON, 순수 텍스트)는 창구 하나에서 바로 접수되지만, 소포(파일)는 무게를 재고 포장 상태를 확인하는 별도의 소포 접수대를 거칩니다. NestJS에서 이 소포 접수대 역할을 하는 것이 Multer입니다. 컨트롤러 메서드에 @UseInterceptors(FileInterceptor('필드명'))을 달아두면, 요청이 핸들러에 도착하기 전에 Multer가 먼저 파일을 받아 디스크에 내려놓습니다. 핸들러는 파일 원본을 직접 다루지 않고, @UploadedFile()로 "그 파일이 어디에 저장됐는지"에 대한 메타데이터만 건네받습니다.

실제 코드에서 컨트롤러 메서드에 붙는 데코레이터를 하나씩 뜯어보면, FileInterceptor('image')의 'image'는 클라이언트가 보낸 폼 데이터에서 파일이 담긴 필드 이름과 정확히 일치해야 합니다. diskStorage는 "받은 파일을 어디에, 어떤 이름으로 저장할지"를 정하는 설정입니다.

typescriptposts.controller.ts — 파일 업로드 엔드포인트
import {
  Controller, Post, UseInterceptors, UploadedFile,
} from '@nestjs/common';
import { FileInterceptor } from '@nestjs/platform-express';
import { diskStorage } from 'multer';
import { extname } from 'path';

@Controller('posts')
export class PostsController {

  @Post('image')
  @UseInterceptors(
    FileInterceptor('image', {
      storage: diskStorage({
        destination: './public/images',
        filename: (req, file, cb) => {
          const unique = Date.now() + '-' + Math.round(Math.random() * 1e9);
          cb(null, unique + extname(file.originalname));
        },
      }),
    }),
  )
  uploadImage(@UploadedFile() file: Express.Multer.File) {
    return { filename: file.filename };
  }
}

filename 콜백을 눈여겨봐야 합니다. 업로드된 파일의 원본 이름(file.originalname)을 그대로 저장 파일명으로 쓰지 않고, Date.now()(타임스탬프)와 난수를 조합해 새 이름을 만듭니다. 만약 원본 이름을 그대로 쓰면 서로 다른 사용자가 우연히 같은 이름(예: profile.jpg)의 파일을 올렸을 때 먼저 저장된 파일을 덮어써 버립니다. 매번 고유한 이름을 새로 만들어야 이런 충돌을 막을 수 있습니다.

여러 파일 업로드 — FilesInterceptor. 한 필드에서 여러 파일을 받으려면 FilesInterceptor('images', 10)(최대 10개)를 쓰고 파라미터를 @UploadedFiles()로 변경합니다. 파일 유형 검증은 fileFilter 옵션에서 file.mimetype을 확인하면 됩니다.

정적 파일 서빙 — ServeStaticModule

파일이 디스크에 저장됐다고 해서 브라우저가 저절로 그 파일을 볼 수 있는 것은 아닙니다. public/images/abc.jpg라는 디스크 경로와, 브라우저가 접속할 URL은 서로 완전히 다른 개념입니다. 이 둘을 이어주는 다리가 없으면 파일은 서버 어딘가에 존재할 뿐, 누구도 URL로 꺼내볼 수 없습니다. @nestjs/serve-static의 ServeStaticModule이 그 다리 역할을 합니다. rootPath는 다리의 시작점(디스크 경로), serveRoot는 다리의 끝점(URL 접두사)입니다.

비유 — 사물함과 열람 창구. 업로드는 파일을 사물함(public/)에 넣는 것, Static Serving은 열람 창구를 여는 것입니다. 사물함 번호(rootPath)를 알려주고 창구 번호(serveRoot)를 정하면, 누구든 그 창구 URL로 파일을 꺼내 볼 수 있습니다. NestJS 코드 없이 파일 자체가 응답이 됩니다.
typescriptapp.module.ts — ServeStaticModule 등록
import { ServeStaticModule } from '@nestjs/serve-static';
import { join } from 'path';

@Module({
  imports: [
    ServeStaticModule.forRoot({
      rootPath: join(__dirname, '..', 'public'),  // 디스크 경로
      serveRoot: '/public',                           // URL 접두사
    }),
  ],
})
export class AppModule {}

등록하면 public/images/abc.jpg는 GET /public/images/abc.jpg로 접근 가능합니다. 업로드 응답에서 filename을 반환하면 클라이언트는 /public/images/{filename}으로 이미지를 표시할 수 있습니다.

POST → Multer(diskStorage) → public/ 디스크 → ServeStaticModule → GET URL. 코드 없이 파일 자체가 응답이 된다.

셀프 체크 — 면접관처럼 물어보기

Q .env 값을 NestJS 코드에서 읽는 방법을 설명하세요.

AppModule에 ConfigModule.forRoot({ isGlobal: true })를 등록합니다. isGlobal: true로 설정하면 다른 모듈에서 ConfigModule을 imports하지 않아도 됩니다.
값이 필요한 서비스 생성자에 ConfigService를 주입하고 this.configService.get<타입>('KEY')으로 읽습니다. .env 파일에 KEY=value 형식으로 선언하면 됩니다.

Q 업로드한 파일을 URL로 보이게 하는 설정은 무엇인가요?

@nestjs/serve-static의 ServeStaticModule.forRoot({ rootPath, serveRoot })를 사용합니다. rootPath에 디스크 경로(예: join(__dirname, '..', 'public')), serveRoot에 URL 접두사(예: '/public')를 지정합니다.
그러면 public/images/abc.jpg 파일이 GET /public/images/abc.jpg로 접근 가능해집니다. NestJS 컨트롤러 없이 파일 자체가 응답이 됩니다.

Q FileInterceptor와 FilesInterceptor의 차이는 무엇인가요?

FileInterceptor('fieldName')은 단일 파일 하나를 받고 파라미터에 @UploadedFile()을 씁니다. FilesInterceptor('fieldName', maxCount)는 같은 필드에서 여러 파일을 받고 파라미터에 @UploadedFiles()를 씁니다. 두 경우 모두 @UseInterceptors()로 메서드에 적용합니다.
