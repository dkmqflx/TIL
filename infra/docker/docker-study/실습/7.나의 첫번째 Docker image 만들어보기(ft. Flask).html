나의 첫번째 Docker 이미지 만들어보기 (ft. Flask)

지금까지 배운 Dockerfile 개념을 실제로 사용해서 나만의 Flask 이미지를 직접 만들어봅니다. app.py와 Dockerfile을 살펴보고, pip install·포트 포워딩·EXPOSE에 대한 Q&A를 거쳐 build → run → 브라우저 확인까지 전체 흐름을 따라갑니다.
🚀1. 들어가며

지금까지 Dockerfile의 개념과 주요 명령어(FROM, WORKDIR, COPY, RUN, EXPOSE, CMD)를 배웠습니다. 이번 실습에서는 이 개념들을 실제로 사용해서 나만의 Flask 이미지를 직접 만들어봅니다. 간단한 웹 서버 하나(app.py)를 Docker 이미지로 빌드하고, 컨테이너로 실행해서 브라우저에서 응답을 확인하는 것까지 전체 흐름을 따라가 봅니다.

💻2. 코드 살펴보기: app.py → Dockerfile
app.py — Flask 애플리케이션

이 실습의 애플리케이션 코드는 실습/7.나의 첫번째 Docker image 만들어보기(ft. Flask)/app.py 입니다.

python
from flask import Flask

app = Flask(__name__)

@app.route('/')
def home():
    return "Welcome to the Docker Lecture App! Thank you"

if __name__ == "__main__":
    app.run(host='0.0.0.0', port=5000)
  • Flask(__name__): Flask 애플리케이션 인스턴스를 생성합니다.
  • @app.route('/'): 루트 경로(/)로 요청이 오면 home() 함수를 실행하도록 연결합니다.
  • return "Welcome to the Docker Lecture App! Thank you": 브라우저에 그대로 표시될 응답 메시지입니다.
  • app.run(host='0.0.0.0', port=5000): 포트 5000에서 서버를 실행합니다. 컨테이너 안에서는 host='0.0.0.0'으로 바인딩해야 컨테이너 바깥(호스트)에서도 접근할 수 있습니다. 127.0.0.1로 두면 컨테이너 내부에서만 접근 가능해 외부 요청이 도달하지 못합니다.
Dockerfile — 이미지 빌드 설계도 (6단계)

실습/7.나의 첫번째 Docker image 만들어보기(ft. Flask)/Dockerfile에는 이미 각 단계에 대한 상세한 한국어 주석이 포함되어 있습니다. 전체 내용은 다음과 같습니다.

dockerfile
# Step 1: Specify the base image
# Use an official lightweight image, such as Python, for simplicity

# python:3.13-slim = Python 3.13 설치된 경량 이미지 (불필요한 패키지 제거로 용량 최소화)
# 다른 옵션: python:3.13 (더 많은 패키지 포함, 크기 커짐)
FROM python:3.13-slim

# Step 2: Set the working directory inside the container
# This is where all commands and files will be located during build

# 컨테이너 내부에 /app 디렉토리를 생성하고, 이를 기본 작업 디렉토리로 설정
# 이후의 모든 RUN, COPY, CMD 등의 명령어는 /app을 기준으로 실행됨
WORKDIR /app

# Step 3: Copy the application code into the container
# "." represents the current directory on the host, and "/app" is the container's directory
# 호스트(개발 컴퓨터)의 현재 디렉토리 모든 파일을 컨테이너의 /app 디렉토리로 복사
# .dockerignore 파일에 명시된 파일/디렉토리는 제외됨 (예: .git, __pycache__, *.pyc)
# 여기에서는 app.py, requirements.txt, README.md 파일이 복사됨
COPY . /app

# Step 4: Install application dependencies
# Use a requirements.txt file for Python dependencies

# pip install: Python 패키지 설치 명령어
# -r requirements.txt: requirements.txt 파일에 명시된 모든 패키지 설치
# --no-cache-dir: pip 캐시를 저장하지 않아 컨테이너 이미지 크기 감소
RUN pip install --no-cache-dir -r requirements.txt

# Step 5: Expose a port
# Inform Docker which port the application will listen on

# EXPOSE는 문서화 목적이며, 실제로 포트를 열지는 않음
# docker run 시 -p 5000:5000 옵션으로 호스트와 컨테이너의 포트를 연결해야 함
EXPOSE 5000

# Step 6: Specify the default command to run the application
# Replace `app.py` with the name of your main Python script

# CMD: 컨테이너가 시작될 때 기본으로 실행할 명령어 지정
# ["python", "app.py"]는 JSON 형식 (권장)
# docker run 시 다른 명령어로 덮어쓸 수 있음: docker run <image> python other_script.py
CMD ["python", "app.py"]

단계별로 정리하면 다음과 같습니다.

Step명령어역할
1FROM python:3.13-slimPython 3.13이 설치된 경량 베이스 이미지 선택
2WORKDIR /app컨테이너 내부 작업 디렉토리를 /app으로 설정
3COPY . /app호스트의 현재 디렉토리(app.py, requirements.txt, README.md)를 /app으로 복사
4RUN pip install --no-cache-dir -r requirements.txtrequirements.txt에 적힌 패키지 설치
5EXPOSE 5000이 앱이 5000번 포트를 사용한다고 문서화
6CMD ["python", "app.py"]컨테이너 시작 시 python app.py 실행
❓3. Q&A로 이해하는 pip install · 포트 포워딩 · EXPOSE
Q1. pip install을 한 건 app을 실행시키기 위한 라이브러리를 설치한 건가?
A. 맞습니다! pip install은 app.py가 필요로 하는 외부 라이브러리들을 설치하는 것입니다.

이 실습 프로젝트의 requirements.txt에는 아래 한 줄만 있습니다.

text
flask==2.3.2

만약 requirements.txt에 다음과 같이 여러 패키지가 적혀 있다면:

text
Flask==2.3.0
requests==2.31.0
numpy==1.24.0

RUN pip install -r requirements.txt 명령어는

  • Flask (웹 프레임워크)
  • requests (HTTP 요청 라이브러리)
  • numpy (수치 계산 라이브러리)

이 라이브러리들을 설치합니다. 이들이 미리 설치되어야 app.py에서 from flask import Flask처럼 import할 수 있습니다.

설치 주체별 정리
설치 주체설치 내용명령어
FROMPython 3.13 (기본 환경)FROM python:3.13-slim
RUN pip installapp.py가 필요한 외부 라이브러리들RUN pip install -r requirements.txt
COPY나의 app.py 소스코드COPY . /app

이 세 가지가 다 있어야 CMD ["python", "app.py"]가 정상 실행됩니다.

Q2. -p 5001:5000은 무슨 뜻인가? (포트 포워딩 이해하기)
A. docker run -p 5001:5000의 -p [호스트 포트]:[컨테이너 포트]는 다음을 의미합니다.
구성요소설명
5001호스트(당신의 컴퓨터) 포트 번호
5000컨테이너(Docker 내부) 포트 번호
역할호스트:5001 ← 연결 → 컨테이너:5000
동작 원리
  • 1. 당신의 브라우저에서 localhost:5001로 접속
  • 2. 호스트 포트 5001로 요청 도착
  • 3. 자동으로 컨테이너 내부의 포트 5000으로 전달
  • 4. 컨테이너 안의 Flask 앱이 포트 5000에서 응답
  • 5. 응답이 다시 호스트로 돌아옴
📘 누가 정하는가?
호스트 포트(5001): 당신이 자유롭게 정함 (원하면 8080, 3000 등으로 변경 가능)
컨테이너 포트(5000): 이미지 안의 애플리케이션이 미리 정함 (app.py에서 port=5000으로 설정됨)
다양한 예시
bash
docker run -p 8080:5000 my-first-docker    # 호스트 8080 ← 컨테이너 5000
docker run -p 3000:5000 my-first-docker    # 호스트 3000 ← 컨테이너 5000
docker run -p 5000:5000 my-first-docker    # 호스트 5000 ← 컨테이너 5000 (같은 포트)
Q3. Dockerfile의 EXPOSE와 포트는 무슨 관계인가?
A. EXPOSE 5000은 다음을 의미합니다.
항목설명
EXPOSE 5000"우리 앱은 포트 5000을 사용합니다"라고 선언하는 것 (문서화 목적)
실제 역할실제로 포트를 여는 것이 아니며, 그 자체로는 아무 것도 하지 않음

포트 5000이 실제로 쓰이게 되는 진짜 원인은 세 단계로 이어집니다.

원인: app.py 포트 설정
app.run(port=5000) — Flask 앱이 포트 5000으로 설정됨
↓
선언: Dockerfile의 EXPOSE 5000
EXPOSE 5000 — "이 앱은 5000을 사용합니다"라고 문서화
↓
연결: docker run -p 연결
docker run -p 5001:5000 my-first-docker — 호스트와 컨테이너 포트를 실제로 연결

따라서:

  • 5000은 app.py가 정한 것 (컨테이너 포트)
  • EXPOSE는 그것을 선언하는 것 (문서화, 실제 연결 없음)
  • 5001은 당신이 정하는 것 (호스트 포트)
▶️4. 실행하기: 빌드 → 실행 → 확인

README.md의 Commands 절을 기준으로, 실습 폴더에서 다음 순서로 진행합니다.

bash
cd "실습/7.나의 첫번째 Docker image 만들어보기(ft. Flask)"

docker build -t my-first-docker .   # Dockerfile을 이용해 이미지 빌드, -t 옵션으로 이미지 이름 지정

docker images                        # 이미지 목록에서 my-first-docker가 생성됐는지 확인

docker run -p 5001:5000 my-first-docker   # 이미지 실행, -p 옵션으로 호스트와 컨테이너의 포트를 연결

컨테이너가 실행된 상태에서 브라우저로 http://localhost:5001에 접속하면 Flask 앱의 응답을 확인할 수 있습니다.

코드를 수정하고 다시 실행하고 싶다면?

app.py의 응답 메시지를 수정한 뒤 다시 확인하려면, 이미지를 다시 빌드해야 합니다. 컨테이너는 빌드 시점의 이미지 내용을 그대로 담고 있기 때문에, 코드만 고치고 기존 컨테이너를 재시작해도 변경 사항이 반영되지 않습니다.

bash
# 1. app.py 수정 후 저장

# 2. 같은 이름으로 이미지를 다시 빌드
docker build -t my-first-docker .

# 3. 이전 컨테이너가 5001 포트를 점유 중이라면 먼저 중지/삭제
docker ps               # 실행 중인 컨테이너 확인
docker stop <container-id>

# 4. 새 이미지로 다시 실행
docker run -p 5001:5000 my-first-docker

이제 다시 http://localhost:5001에 접속하면 수정된 메시지가 표시됩니다.

✅5. 예상 결과

컨테이너가 정상적으로 실행되고 있다면, 브라우저에서 http://localhost:5001에 접속했을 때 다음 메시지가 표시됩니다.

Welcome to the Docker Lecture App! Thank you

이 문자열은 app.py의 home() 함수가 그대로 반환하는 값입니다. 메시지가 보인다면 Dockerfile로 이미지를 빌드하고, 포트 포워딩으로 호스트와 컨테이너를 연결하는 전체 흐름이 성공적으로 동작한 것입니다.
