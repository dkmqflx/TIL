Docker Volume 실습

04강에서 배운 Docker Volume 개념을 바탕으로, 이번에는 명령어를 실제로 손으로 타이핑하며 동작을 확인합니다. General/Image/Container 명령어를 다시 한 번 복습하고, 볼륨 생성 → 컨테이너 마운트 → 데이터 쓰기 → 컨테이너 삭제 → 재생성 후 데이터 유지 확인까지 전체 흐름을 순서대로 따라갑니다.
🚀1. 들어가며

이 문서는 04강. Docker Volume 완전 정복의 실습 관점 보충 문서입니다. Volume이 왜 필요한지, Anonymous/Named Volume과 Bind Mount의 차이, 4가지 핵심 특징 같은 이론은 04강에서 이미 다뤘으므로 여기서는 반복하지 않습니다. 대신 지금까지 배운 Docker CLI 명령어 전반을 한 번 더 복습하고, 볼륨 명령어를 실제로 타이핑하면서 컨테이너를 지워도 볼륨 데이터는 남는다는 사실을 직접 확인하는 데 집중합니다.

📘 참고: 개념이 헷갈리면 언제든 04강 Docker Volume 완전 정복 문서를 다시 열어보세요. 이 문서의 모든 실습은 04강에서 설명한 -v [volume-name]:[container-path] 구문을 그대로 사용합니다.
💻2. CLI 명령어 복습

본격적인 Volume 실습에 앞서, 지금까지 배운 기본 명령어들을 카테고리별로 다시 훑어봅니다.

General Docker Commands
bash
# 현재 설치된 Docker의 버전을 출력합니다.
docker --version

# Docker 전체 시스템 정보를 출력합니다.
# 실행 중인 컨테이너 수, 이미지 수, 스토리지 드라이버 종류 등을 확인할 수 있습니다.
docker info

# 사용 가능한 모든 Docker 명령어와 옵션 목록을 출력합니다.
docker help
Image Management
이미지(Image)란? 컨테이너를 만들기 위한 '설계도'입니다. 예를 들어 nginx 이미지를 받아서 여러 개의 nginx 컨테이너를 실행할 수 있습니다.
bash
# 로컬(내 컴퓨터)에 저장된 이미지 목록을 출력합니다.
docker images

# Docker Hub(공개 이미지 저장소)에서 이미지를 다운로드합니다.
# 예: docker pull nginx
docker pull [image-name]

# 현재 디렉토리의 Dockerfile을 사용해 이미지를 빌드하고 이름을 붙입니다.
# -t: 이미지에 이름(태그)을 붙이는 옵션
# . : Dockerfile이 있는 현재 디렉토리를 의미
docker build -t [image-name] .

# 이미지에 다른 이름이나 버전 태그를 붙입니다.
# 예: docker tag my-app my-app:v1.0
docker tag [source-image] [target-image:tag]

# 이미지를 Docker Hub 같은 레지스트리에 업로드합니다.
docker push [image-name]

# 이미지를 삭제합니다. (실행 중인 컨테이너가 사용 중인 이미지는 삭제 불가)
docker rmi [image-id]
Container Management
컨테이너(Container)란? 이미지를 실행한 인스턴스입니다. 이미지가 '설계도'라면 컨테이너는 그 설계도로 만든 '실제 건물'입니다.
bash
# 현재 실행 중인 컨테이너 목록을 출력합니다.
docker ps

# 중지된 컨테이너를 포함해 모든 컨테이너 목록을 출력합니다.
docker ps -a

# 이미지로부터 컨테이너를 생성하고 실행합니다.
docker run [options] [image-name]
    # 자주 쓰이는 옵션들:
    -d                              # 백그라운드(detached)에서 실행. 터미널을 점유하지 않음
    -p [host-port]:[container-port] # 호스트 포트와 컨테이너 포트를 연결(포트 포워딩)
                                    # 예: -p 8080:80 → 내 컴퓨터의 8080으로 접속하면 컨테이너의 80 포트로 연결
    --name [container-name]         # 컨테이너에 이름을 지정 (없으면 Docker가 랜덤 이름 생성)
    -v [host-path]:[container-path] # 볼륨(저장소)을 마운트 → 아래 실습에서 직접 다뤄봅니다.

# 컨테이너를 삭제합니다. (먼저 중지한 후 삭제해야 함)
docker rm [container-id/name]

# 실행 중인 컨테이너를 강제로 삭제합니다. (-f = force)
docker rm -f [container-id/name]

# 실행 중인 컨테이너를 중지합니다.
docker stop [container-id/name]

# 중지된 컨테이너를 다시 시작합니다.
docker start [container-id/name]

# 컨테이너를 재시작합니다. (stop → start를 한 번에)
docker restart [container-id/name]
Container Interaction
bash
# 실행 중인 컨테이너 안에서 명령어를 실행합니다.
# -it: 인터랙티브 터미널 모드 (직접 입력을 주고받을 수 있게 함)
# 예: docker exec -it [container-id] /bin/bash → 컨테이너 내부의 bash 셸을 열어 직접 조작
docker exec [container-id/name] [command]

# 컨테이너의 로그를 출력합니다.
docker logs [options] [container-id/name]
    --follow    # 로그를 실시간으로 스트리밍 (Ctrl+C로 종료)

# 실행 중인 컨테이너의 표준 입출력에 내 터미널을 연결합니다.
# exec와의 차이: exec는 새 프로세스를 실행, attach는 기존 메인 프로세스에 붙음
docker attach [container-id/name]

# 컨테이너를 즉시 강제 종료합니다.
# SIGKILL: 프로세스를 즉시 죽이는 신호 (저장 없이 강제 종료)
# SIGTERM: 정상 종료를 요청하는 신호 (프로세스가 정리 후 종료)
docker kill [options] [container-id/name]
    --signal, -s    # 보낼 신호를 지정 (기본값: SIGKILL)
Debugging Commands
bash
# 컨테이너, 이미지, 네트워크 등의 상세 정보를 JSON 형식으로 출력합니다.
# IP 주소, 볼륨 마운트 경로, 환경 변수 등을 확인할 때 유용
docker inspect [object-id/name]

# 실행 중인 컨테이너들의 CPU, 메모리 등 리소스 사용량을 실시간으로 출력합니다.
docker stats [container-id/name]

# 컨테이너 안에서 실행 중인 프로세스 목록을 출력합니다.
docker top [container-id/name]

# Docker 데몬에서 발생하는 이벤트를 실시간으로 출력합니다.
# 컨테이너 시작/중지, 이미지 pull 등의 이벤트 확인 가능
docker events
🗄️3. Volume 명령어
📌 개념은 여기서 다시 설명하지 않습니다. Volume이 왜 필요한지, Anonymous/Named Volume과 Bind Mount의 차이, Volume의 4가지 핵심 특징, best practice 등 이론 전반은 04강. Docker Volume 완전 정복 문서를 참고하세요. 이 문서(실습 8강)는 그 이론을 바탕으로 명령어를 실제로 손으로 타이핑하며 볼륨의 동작을 직접 확인하는 데 집중합니다.
bash
# 새로운 볼륨을 생성합니다.
# Docker가 내부적으로 저장 공간을 만들어 관리합니다.
docker volume create my_volume

# 현재 존재하는 볼륨 목록을 출력합니다.
docker volume ls

# 특정 볼륨의 상세 정보를 출력합니다.
# 볼륨이 실제로 저장된 호스트 경로(Mountpoint) 등을 확인할 수 있습니다.
docker volume inspect my_volume

# 볼륨을 삭제합니다. (사용 중인 볼륨은 삭제 불가)
docker volume rm my_volume

# 어떤 컨테이너에서도 사용되지 않는 볼륨을 모두 삭제합니다.
# 디스크 공간을 정리할 때 유용 (주의: 복구 불가)
docker volume prune
🔁4. 실습 1: Named Volume 생성부터 데이터 유지 확인까지

이 실습의 목표는 "컨테이너를 삭제해도 볼륨에 저장한 데이터는 그대로 남아있다"는 것을 직접 눈으로 확인하는 것입니다. 전체 흐름은 다음 5단계로 진행합니다.

1단계 — 볼륨 생성
docker volume create my_volume
↓
2단계 — 컨테이너에 마운트
docker run -v my_volume:/data busybox sh
↓
3단계 — 데이터 쓰기
echo "..." > /data/hello.txt
↓
4단계 — 컨테이너 삭제 확인
docker ps -a로 컨테이너 소멸 확인
↓
5단계 — 재생성 후 데이터 유지 확인
새 컨테이너에서 cat /data/hello.txt
0단계: 실습 전 상태 확인
bash
# 현재 존재하는 볼륨 목록을 확인합니다. (아직 my_volume은 없는 것이 정상)
docker volume ls

# 현재 실행 중이거나 중지된 컨테이너 목록을 확인합니다.
docker ps -a
1단계: 볼륨 생성
bash
# 'my_volume'이라는 이름의 볼륨을 생성합니다.
docker volume create my_volume

# 목록에 my_volume이 추가됐는지 확인합니다.
docker volume ls
# 예시 출력:
# DRIVER    VOLUME NAME
# local     my_volume

# 볼륨이 호스트의 어느 경로에 저장되는지 상세 정보로 확인합니다.
docker volume inspect my_volume
# "Mountpoint": "/var/lib/docker/volumes/my_volume/_data" 형태의 경로가 출력됩니다.
# 이 시점에는 아직 아무 파일도 쓰지 않았으므로 비어 있는 폴더입니다.
2단계: 컨테이너를 실행하며 볼륨 마운트
bash
# busybox 컨테이너를 실행하면서 my_volume을 컨테이너 내부 /data 경로에 연결합니다.
# --rm  : 컨테이너가 종료되면 컨테이너 자체는 자동으로 삭제 (볼륨은 영향 없음)
# -it   : 인터랙티브 터미널 모드 (직접 명령어를 입력하기 위해 필요)
# -v my_volume:/data : 'my_volume' 볼륨을 컨테이너 내부의 /data 경로에 연결
# busybox : 매우 가벼운 리눅스 이미지 (실습용으로 자주 사용)
# sh    : 컨테이너 실행 후 sh(셸)를 시작
docker run --rm -it -v my_volume:/data busybox sh
3단계: 컨테이너 내부에서 데이터 쓰기
bash
    # --- 여기서부터는 busybox 컨테이너 내부 ---

    # /data 디렉토리 내용을 먼저 확인합니다. (1단계에서 확인한 것처럼 아직 비어 있음)
    ls -al /data

    # /data 디렉토리에 hello.txt 파일을 생성합니다.
    # /data 는 my_volume을 마운트한 경로이므로, 이 파일은 컨테이너가 아니라 볼륨에 저장됩니다.
    echo "Hello, Docker Volumes!" > /data/hello.txt

    # 파일이 제대로 저장됐는지 컨테이너 내부에서 바로 확인합니다.
    cat /data/hello.txt

    # 컨테이너를 종료합니다. --rm 옵션으로 인해 컨테이너는 자동으로 삭제됩니다.
    exit
4단계: 컨테이너 삭제 확인
bash
# 방금 사용한 컨테이너가 --rm 옵션으로 실제로 삭제됐는지 확인합니다.
docker ps -a
# 위 목록에 방금 exit한 컨테이너가 더 이상 보이지 않으면 정상입니다. (자동 삭제됨)

# 컨테이너는 사라졌지만, 볼륨은 컨테이너와 별개로 Docker가 관리하므로 그대로 남아 있습니다.
docker volume ls
# my_volume이 여전히 목록에 있어야 합니다.
✅ 체크포인트: 컨테이너는 docker ps -a 목록에서 사라졌지만, docker volume ls에는 my_volume이 그대로 남아 있어야 합니다. 이것이 바로 컨테이너와 볼륨의 생명주기가 분리되어 있다는 증거입니다.
5단계: 컨테이너 재생성 후 데이터 유지 확인
bash
# 완전히 새로운 컨테이너를 실행하되, 같은 my_volume을 그대로 마운트합니다.
# (컨테이너는 3단계에서 쓰던 것과 다른 "새 컨테이너"이지만, 볼륨은 동일한 my_volume입니다.)
docker run --rm -it -v my_volume:/data busybox sh

    # --- 새로 생성된 컨테이너 내부 ---

    # 이전 컨테이너에서 저장한 파일이 여전히 존재하는지 목록으로 확인합니다.
    ls -al /data

    # 파일 내용을 읽습니다.
    # "Hello, Docker Volumes!" 가 그대로 출력되면, 컨테이너를 삭제한 뒤 새로
    # 만들어도 볼륨의 데이터는 유지된다는 것이 확인된 것입니다.
    cat /data/hello.txt

    exit
정리(clean up)
bash
# 실습이 끝났다면 더 이상 필요 없는 볼륨을 삭제해 정리합니다.
# (컨테이너는 이미 모두 --rm으로 삭제되었으므로 바로 삭제 가능합니다.)
docker volume rm my_volume

# 목록에서 my_volume이 사라졌는지 확인합니다.
docker volume ls
🤝5. 실습 2: 두 컨테이너 간 볼륨 공유

두 컨테이너가 같은 볼륨을 공유하면 데이터를 서로 주고받을 수 있습니다. 예를 들어 하나의 컨테이너가 로그를 쓰고, 다른 컨테이너가 그 로그를 읽는 구조를 만들 수 있습니다.

bash
# 1단계: 첫 번째 컨테이너에서 'shared_volume'에 파일을 씁니다.
# (볼륨을 미리 생성하지 않아도, -v 옵션에서 자동으로 생성됩니다)
docker run --rm -it -v shared_volume:/shared busybox sh

    # --- 첫 번째 컨테이너 내부 ---

    # /shared 경로(= shared_volume)에 파일을 저장합니다.
    echo "Shared Data" > /shared/shared_file.txt

    # 컨테이너를 종료합니다.
    exit

# 2단계: 첫 번째 컨테이너가 삭제된 뒤에도 볼륨 자체는 남아있는지 확인합니다.
docker volume ls
# shared_volume이 목록에 있어야 합니다. (-v 옵션이 자동으로 생성한 볼륨)

# 3단계: 두 번째 컨테이너에서 같은 볼륨을 마운트해 파일을 읽습니다.
docker run --rm -it -v shared_volume:/shared busybox sh

    # --- 두 번째 컨테이너 내부 ---

    # 첫 번째 컨테이너에서 저장한 파일을 읽습니다.
    # "Shared Data"가 출력되면 볼륨 공유가 성공한 것입니다.
    cat /shared/shared_file.txt

    # 두 번째 컨테이너에서도 파일을 추가로 써봅니다.
    echo "Written by second container" >> /shared/shared_file.txt

    exit

# 4단계: 정리 — 실습이 끝났다면 공유 볼륨도 삭제합니다.
docker volume rm shared_volume
docker volume ls
📋6. 핵심 정리
단계한 줄 요약
볼륨 생성docker volume create로 Docker가 관리하는 저장 공간을 만듭니다.
컨테이너 마운트-v [volume-name]:[container-path]로 컨테이너 내부 경로에 볼륨을 연결합니다.
데이터 쓰기마운트된 경로에 쓴 파일은 컨테이너가 아니라 볼륨에 저장됩니다.
컨테이너 삭제컨테이너를 삭제해도(--rm, docker rm) 볼륨은 영향을 받지 않습니다.
재생성 후 확인같은 볼륨을 새 컨테이너에 마운트하면 이전 데이터를 그대로 읽을 수 있습니다.
🚀 핵심 한 문장: 컨테이너의 생명주기와 볼륨의 생명주기는 서로 분리되어 있으며, 이 실습에서 직접 확인한 흐름(생성 → 마운트 → 쓰기 → 삭제 → 재생성 → 확인)이 바로 그 증거입니다. 더 깊은 개념은 언제든 04강을 참고하세요.
