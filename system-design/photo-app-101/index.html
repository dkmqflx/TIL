포토앱으로 배우는 시스템 디자인

개념을 하나씩 외우는 대신, 사진 공유 앱 하나를 서버 한 대에서 시작해 수백만 명이 쓰는 서비스로 키워 봅니다. 부품(로드 밸런서·캐시·복제·샤딩)은 "앱이 실제로 고장 나는 순간"에만 등장하기 때문에, 각 부품이 왜 거기 있는지를 자연스럽게 알게 됩니다.

Load Balancer Stateless Data Modeling SQL vs NoSQL Index Cache Replication Sharding
이 가이드를 읽는 법: 각 Part는 "앱이 이렇게 고장 났다 → 왜 그런가 → 어떤 부품으로 고치나 → 그 부품이 새로 만드는 문제는 뭔가" 순서로 이어집니다. 그래서 순서대로 읽는 게 가장 잘 이해돼요. 다 읽고 나면 "이 앱을 어떻게 확장할래?"라는 질문에 다이어그램을 외워서 답하는 게 아니라, 논리적으로 설명할 수 있게 되는 게 목표입니다.
