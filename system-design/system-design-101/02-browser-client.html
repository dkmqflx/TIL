클라이언트 vs 브라우저

시스템 디자인에서 브라우저(클라이언트)는 사용자에게 가장 많이 노출되는 부품입니다. 시스템의 가장 앞선(최전선)에서 사용자와 직접 대화하는 역할이죠. 그런데 '클라이언트'와 '브라우저'는 자주 섞어 쓰지만, 사실 다른 뜻입니다.

📱
클라이언트 (Client)
서버에 요청을 보내는 쪽을 통틀어 부르는 넓은 개념. 스마트폰·노트북 같은 기기일 수도, 앱 같은 프로그램일 수도 있습니다.
🌐
브라우저 (Browser)
클라이언트의 한 종류. 웹페이지를 불러와 화면에 보여주는 소프트웨어입니다. (크롬, 사파리, 엣지…)
핵심 관계 — 브라우저는 클라이언트에 "속한다"
즉 브라우저 ⊂ 클라이언트. 모든 브라우저는 클라이언트지만, 모든 클라이언트가 브라우저는 아닙니다. (예: 모바일 앱, 게임 클라이언트, curl 같은 명령어 도구도 전부 클라이언트예요.)
비유 — "손님"과 "웹 보러 온 손님"
가게에 오는 손님 전체가 클라이언트라면, 그중 "웹사이트를 보러 온 손님"이 브라우저입니다. 손님에는 전화 주문 손님(모바일 앱), 배달 손님(다른 프로그램)도 있으니까요.
🌐

브라우저가 하는 일

브라우저는 우리가 인터넷을 접속하는 창구입니다. 하는 일을 크게 3가지로 나눌 수 있어요.

🔎
1. 웹페이지 탐색
주소창에 입력한 곳으로 이동해 웹페이지(데이터)를 불러옵니다.
🎨
2. 화면에 표시 (렌더링)
불러온 HTML·CSS를 사람이 볼 수 있는 화면으로 그려줍니다.
👆
3. 상호작용 처리
클릭·입력 같은 사용자 동작을 받아 반응합니다.
정리하면 브라우저는 "불러오고 → 그리고 → 반응하는" 일을 합니다. 이 3가지가 어떻게 이뤄지는지, 지금부터 주소창에 URL을 입력하는 순간을 따라가며 살펴봅니다.
🚀

URL을 입력하면 벌어지는 일

주소창에 youtube.com을 치고 엔터를 누르면, 화면이 뜨기까지 눈에 안 보이는 여러 단계가 순식간에 일어납니다. 하나씩 따라가 볼게요.

1
DNS 조회 — 도메인을 IP 주소로 변환
youtube.com이라는 이름을 컴퓨터가 알아듣는 IP 주소(예: 142.250.x.x)로 바꿉니다. (바로 아래 섹션에서 자세히!)
2
HTTP(S) 요청 — 서버에 "페이지 주세요"
알아낸 IP 주소로 접속해 HTTP 또는 HTTPS로 "이 페이지 데이터를 달라"고 요청합니다.
3
서버 응답 — HTML·CSS·JS 도착
서버가 요청을 받아 웹페이지를 이루는 HTML·CSS·JavaScript 파일들을 돌려줍니다.
4
렌더링 — 받은 코드를 화면으로
브라우저가 받은 HTML 구조(DOM)를 바탕으로 실제 화면을 그립니다. (아래 '화면에 그려지는 과정' 참고)
5
사용자 상호작용 — 클릭하면 반응
이제 JavaScript가 버튼 클릭·폼 입력 같은 이벤트를 처리합니다. 클릭 한 번에 다시 서버로 요청이 나가기도 하죠.

DNS: 인터넷 전화번호부

1단계였던 DNS 조회는 초보자에게 가장 낯선 부분이라 따로 자세히 볼게요.

비유 — 스마트폰 연락처
전화를 걸 때 우리는 "010-1234-…" 번호를 외우지 않고 "엄마"라는 이름을 누릅니다. 연락처 앱이 이름을 실제 번호로 바꿔주니까요.
인터넷도 똑같습니다. 우리는 youtube.com이라는 이름을 치지만, 컴퓨터끼리는 IP 주소라는 숫자로 통신합니다. 이 이름 → 숫자 변환을 해주는 게 DNS(Domain Name System)예요.

DNS는 어떤 순서로 IP를 찾을까?

1
먼저 캐시(기억) 확인
"전에 이 사이트 가본 적 있나?" 브라우저가 캐시에 저장해 둔 IP가 있으면 바로 그걸 씁니다. 조회 과정을 통째로 건너뛰니 제일 빠르죠.
2
캐시에 없으면 DNS 서버에 물어봄
보통 ISP(인터넷 서비스 제공업체, 예: KT·SK)가 운영하는 DNS 리졸버에게 "youtube.com의 IP가 뭐야?"라고 요청합니다.
3
IP 주소를 받아서 접속
DNS 리졸버가 IP를 찾아 돌려주면, 브라우저는 그 IP로 실제 접속을 시작합니다. (이 결과도 다음을 위해 캐시에 저장!)

화면에 그려지는 과정 (렌더링)

서버가 돌려준 HTML은 사실 글자로 된 설계도일 뿐입니다. 브라우저는 이 설계도를 읽어 실제 화면으로 그려내는데, 이 과정을 렌더링(rendering)이라고 합니다.

1
HTML → DOM 트리
브라우저가 HTML을 읽어 DOM이라는 나무 모양의 구조로 바꿉니다. "제목 안에 글자, 그 아래 버튼…" 같은 구조·뼈대를 만드는 단계예요.
2
CSS → 스타일 입히기
CSS를 읽어 "이 글자는 빨간색, 이 버튼은 둥글게" 같은 디자인(옷)을 뼈대에 입힙니다.
3
화면에 그리기
구조 + 디자인을 합쳐 실제 픽셀로 화면에 그립니다. 드디어 우리 눈에 페이지가 보입니다.
4
JavaScript로 살아 움직이게
JS가 이벤트를 처리합니다. 버튼 클릭·폼 제출 같은 상호작용을 받아 화면을 바꾸거나 서버에 새 요청을 보내죠. JS는 이벤트 기반 언어라 "무슨 일이 일어나면 → 무엇을 한다"로 동작합니다.
비유 — 집을 완성하는 과정
HTML(뼈대·골조) → CSS(페인트·인테리어) → 화면 그리기(입주 완료) → JavaScript(전등 스위치·초인종처럼 눌렀을 때 반응하는 것들).

🏗️
웹 개발의 기본기
브라우저가 어떻게 페이지를 불러오고 그리는지 알아야, 그 위에서 제대로 된 웹을 만들 수 있습니다.
⚡
성능 최적화
캐싱과 렌더링 과정을 이해하면 페이지를 더 빠르게 만들 수 있습니다.
😊

빠르고 매끄러운 화면은 곧 좋은 UX로 이어집니다.
