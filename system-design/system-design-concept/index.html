SYSTEM DESIGN · 크래시 코스

시스템 디자인 개념 완전판

컴퓨터 한 대의 구조부터 대규모 분산 시스템까지 — 시스템 디자인 면접에 필요한 핵심 개념을 비유와 예시로 하나씩 풀어냅니다. 코드를 짜는 게 아니라 전체를 어떻게 조립하는가를 배우는 자료입니다.

Computer Architecture CAP Availability TCP / UDP HTTP / HTTPS API Design Caching / CDN Proxy / LB Database
이 자료를 읽는 법 — 시스템 디자인은 "코드"가 아니라 "큰 그림"을 다룹니다. 그래서 용어를 통째로 외우려 하지 말고, "이 부품이 왜 여기 있지?"라는 질문에 스스로 답할 수 있게 되는 걸 목표로 읽어보세요. Part 1(컴퓨터 한 대)에서 시작해 Part 9(대규모 데이터베이스)까지, 점점 더 큰 그림으로 확장됩니다. 한 개념은 한 곳에서만 자세히 설명하고, 다른 Part에서는 링크로 되돌아갑니다.
🛤️

비유 — 건물 한 채를 이해하는 순서
먼저 벽돌과 철근(컴퓨터 부품)을 알고, 완성된 건물을 한 바퀴 둘러본 뒤(서비스 전체 구조), 좋은 건물의 기준(확장성·가용성·CAP)을 정합니다. 그다음 도로와 배관(네트워크·프로토콜), 출입구 규칙(API)을 보고, 마지막으로 사람이 몰릴 때 필요한 편의시설(캐시·로드밸런서·DB 확장)을 붙입니다. Part 3의 "무엇을 양보할지 정하는 게 설계다"라는 문장이 뒤의 모든 선택을 관통합니다.
